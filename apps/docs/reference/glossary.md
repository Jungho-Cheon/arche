# 용어집

문서를 읽다 모르는 말이 나오면 여기서 찾으세요. 같은 것을 부르는 다른 이름도 함께 적어 두었으니, "점이랑 노드가 같은 말인가" 싶을 때 확인하면 됩니다.

## 기본이 되는 말

**그래프**
점과 선으로 관계를 나타낸 지도입니다. 회사나 정책 같은 대상을 점으로 찍고 그 사이를 선으로 이어, 무엇이 무엇과 어떻게 연결되는지 한눈에 담습니다. Arche 는 문서를 이 지도로 바꿔 둡니다.

**노드 (= 점 = 엔티티)**
그래프의 한 점입니다. 회사, 정책, 상품처럼 하나의 대상을 가리킵니다. 문서마다 "점", "노드", "엔티티" 라는 말이 섞여 나오는데 셋 다 같은 것을 부르는 이름입니다.

**관계 (= 선 = 엣지/edge)**
두 노드를 잇는 연결입니다. "이 정책이 저 상품에 적용된다" 처럼 대상과 대상이 어떻게 얽히는지를 담습니다. "선", "관계", "엣지(edge)" 는 모두 같은 것을 가리킵니다.

**적재 (ingest)**
문서를 읽어 노드와 관계로 뽑아 그래프에 넣는 일입니다. 글과 PDF, 이미지에서 점과 선을 뽑아 저장하고, 같은 문서를 다시 넣으면 바뀐 부분만 갱신합니다. 영어로는 ingest 라고 씁니다.

**청크 (= 토막)**
긴 문서를 나눈 한 조각입니다. 문서를 통째로 다루지 않고 적당한 크기로 잘라 처리하는데, 그 한 조각을 "청크" 또는 "토막" 이라 부릅니다. 두 말은 같은 뜻입니다.

## 쓰면서 만나는 말

**그래프 조회 연산**
Arche 가 제공하는 여섯 가지 기본 조회입니다. 그래프에서 답에 필요한 부분만 조금씩 꺼내 보는 도구라고 보면 됩니다.

- 그래프 모양 보기 — 어떤 종류의 점과 선이 얼마나 들었는지 훑어봅니다.
- 시작점 찾기 — 키워드로 출발점이 될 노드를 찾습니다.
- 한 노드 보기 — 노드 하나의 자세한 내용을 봅니다.
- 이웃 펼치기 — 한 노드에서 몇 단계 안에 닿는 이웃을 펼쳐 봅니다.
- 두 노드 사이 경로 찾기 — 두 노드를 잇는 짧은 길을 찾습니다.
- 부분 그래프 모으기 — 여러 시작점에서 펼친 결과를 하나로 합칩니다.

**에이전트**
Arche 를 반복해서 부르며 답을 찾아가는 AI 프로그램입니다. 사람이 던진 질문 하나를 받아 그래프를 여러 번 되물으며 스스로 답을 좁혀 갑니다. 에이전트는 Arche 안에 들어 있지 않고, Arche 를 쓰는 쪽이 직접 만듭니다.

**MCP**
AI 에이전트가 외부 도구를 정해진 방식으로 부르게 해 주는 약속입니다. 도구마다 이름과 입력 형식이 정해져 있어, 에이전트는 그 규격대로 부르기만 하면 됩니다. Model Context Protocol 의 줄임말이고, Arche 는 그래프 조회를 MCP 로도 열어 둡니다.

**namespace**
여러 팀의 지식을 한 그래프 안에 두면서 서로 섞이지 않게 갈라 두는 칸막이입니다. 그래프 DB 는 하나만 두고, 각 팀의 데이터와 조회를 저마다의 칸 안에 가둬 다른 팀으로 새지 않게 합니다. 칸을 따로 정하지 않은 요청은 `default` 라는 칸으로 갑니다.

**임베딩**
글의 의미를 숫자 목록(벡터)으로 바꾼 것입니다. 뜻이 비슷한 글일수록 숫자가 가깝게 놓여서, 표현이 조금 달라도 의미가 통하는 노드를 찾아낼 수 있습니다. 시작점을 찾는 검색에 씁니다.

**ULID**
노드마다 하나씩 붙는 식별자입니다. 숫자와 대문자로만 된 26글자로, 만들어진 시간 순서대로 정렬됩니다. 사람이 외우라고 만든 값은 아니고, 노드를 정확히 가리킬 때 씁니다.

**hub_score**
경로가 "아무 데나 연결된 노드" 를 얼마나 거쳐 가는지 나타내는 값입니다. 값이 낮을수록 더 구체적이고 믿을 만한 연결이고, `0` 이면 가장 단단한 직접 연결입니다. 값이 클수록 수많은 것과 얽힌 노드를 다리로 삼은 경로라, 근거로 삼기 전에 한 번 의심해 볼 신호입니다.

## 성능을 견줄 때 나오는 이름

**graphify**
정확도를 견줘 본 비교 기준 도구입니다. 문서마다 따로 그래프를 만들고 에이전트가 그 위에서 질의하는 방식으로, 문서 사이의 같은 대상을 하나로 합치지는 않습니다. 그래서 문서마다 고립된 섬이 되는 경향이 있고, 이 차이가 Arche 와의 정답률 격차를 만든 핵심입니다. 사용자가 Arche 대신 쓰는 제품이 아니라 같은 조건에서 정답률을 나란히 놓고 잰 상대로 읽으면 됩니다. 간판 수치가 이 비교 하나에 걸려 있으므로, "특정 비교 대상 하나를 이긴 결과"로 받아들이는 편이 정확합니다.

**FinanceBench**
여러 회사의 재무 보고서로 만든 공개 평가셋입니다. 보기 중에서 정답을 고르는 문제 묶음으로, 재무 도메인에서 정확도를 잴 때 씁니다.

**MedHop**
생물의학 문헌으로 만든 공개 평가셋입니다. 여러 문서에 걸친 관계를 따라가야 풀리는 문제 묶음으로, 관계를 잇는 능력을 잴 때 씁니다.
