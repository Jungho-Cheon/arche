# 용어집

Arche 문서에 나오는 용어를 한자리에 모았습니다. 본문에서 처음 보는 말이 나오면 여기서 찾아보세요.

## 그래프

**노드(node).** 그래프의 점입니다. 회사, 정책, 상품처럼 문서에 나오는 하나의 대상을 가리킵니다. 문서에 따라 엔티티라고도 부르는데, Arche 문서에서는 노드로 통일합니다.

**관계(relation).** 그래프의 선입니다. 노드와 노드를 잇고 방향과 타입을 갖습니다. 응답 JSON 에서는 `edges` 로 실립니다.

**홉(hop).** 선을 한 번 건너는 것입니다. 2홉 이웃은 선을 두 번까지 따라가 닿는 노드를 말합니다.

**ULID.** Arche 가 노드와 관계에 붙이는 26자리 식별자입니다. 대문자와 숫자만 씁니다. 형식은 `^[0-9A-Z]{26}$` 입니다.

**진입점(entry point).** 그래프 탐색을 시작할 노드입니다. `find_entities` 가 키워드를 받아 진입점 후보를 돌려줍니다.

**hub_score.** 경로가 얼마나 두루뭉술한 노드를 거쳐 갔는지를 나타내는 값입니다. 높을수록 아무데나 이어진 노드를 다리로 삼은 경로라 근거로 쓰기 어렵습니다. 판단 기준은 [경로 품질과 hub_score](/query/path-quality)에서 다룹니다.

**namespace.** 한 저장소 안에서 지식을 나눠 담는 칸입니다. 다른 namespace 의 데이터는 검색과 조회에서 보이지 않습니다. 접근 통제는 아닙니다. 자세한 경계는 [namespace 로 나눠 담기](/operate/namespace)에 있습니다.

## 적재

**적재(ingest).** 문서에서 노드와 관계를 뽑아 그래프에 저장하는 일입니다.

**추출(extraction).** 적재의 앞 단계로, AI 모델이 문서를 읽고 노드와 관계를 뽑아내는 일입니다.

**청크(chunk).** 큰 문서를 추출하려고 나눈 조각입니다. 문서가 설정한 크기를 넘으면 자동으로 나뉩니다.

**동일성 해소.** 여러 문서에 흩어져 나온 같은 대상을 하나의 노드로 모으는 일입니다. 이게 되어야 문서를 건너뛰는 질문에 답할 수 있습니다.

**차분(delta).** 같은 출처를 다시 넣을 때 바뀐 부분만 반영하는 것입니다. 같은 `source_id` 나 같은 경로를 써야 차분으로 처리됩니다.

**검토형 적재.** 계획, 미리 보기, 질문 해소, 확정 순서로 사람이 확인한 뒤에 그래프에 쓰는 방식입니다. [적재 도구 참조표](/ingest/tools)에 다섯 도구가 정리돼 있습니다.

**hints.** 추출 품질을 끌어올리려고 함께 넘기는 짧은 메모입니다. 도메인 용어 풀이나 강조할 대상을 적습니다. 저장된 원문은 바뀌지 않습니다.

## 검색

**임베딩(embedding).** 글을 숫자 벡터로 바꾸는 변환입니다. 뜻이 가까운 글끼리 벡터도 가까워져서, 표현이 달라도 비슷한 내용을 찾을 수 있습니다.

**어휘 검색(lexical search).** 낱말이 그대로 일치하는지로 찾는 방식입니다.

**벡터 검색(dense search).** 임베딩끼리의 거리로 찾는 방식입니다. 표현이 달라도 뜻이 가까우면 걸립니다.

**하이브리드 검색.** 어휘 검색과 벡터 검색을 함께 돌려 결과를 합치는 방식입니다. `find_entities` 가 이렇게 동작합니다.

**RRF(Reciprocal Rank Fusion).** 서로 다른 검색 결과를 순위 기준으로 합치는 방법입니다. 점수 체계가 다른 두 결과를 순위로 환산해 더합니다.

## 연결

**MCP(Model Context Protocol).** AI 에이전트가 외부 도구를 정해진 방식으로 부르게 해 주는 규약입니다. Arche 를 쓰는 기본 통로입니다.

**stdio 전송.** 에이전트와 Arche 가 같은 기계에 있을 때 프로세스를 파이프로 잇는 방식입니다. `arche mcp serve --stdio` 가 이걸 띄웁니다.

**HTTP 전송.** 네트워크 너머 원격 에이전트를 붙일 때 쓰는 방식입니다. API 서버가 `/mcp/v1` 에 마운트합니다.

**에이전트(agent).** 질문 하나를 받으면 도구를 여러 번 되물어 가며 스스로 답을 좁혀 가는 AI 프로그램입니다. Arche 는 답을 만들지 않고 에이전트가 만듭니다.

**REST API.** 에이전트를 쓰지 않고 HTTP 로 직접 부르는 통로입니다. 조회 7개가 MCP 와 같은 스키마로 올라옵니다.

**엔드포인트(endpoint).** HTTP 로 부를 수 있는 하나의 주소입니다. `POST /entities/find` 처럼 메서드와 경로가 짝을 이룹니다.

## 저장소

**임베디드(embedded) 데이터베이스.** 별도 서버 없이 프로그램에 딸려 들어가 파일에 저장하는 데이터베이스입니다. SQLite 를 떠올리면 됩니다. Arche 는 Kuzu 를 씁니다.

**Kuzu.** Arche 의 기본 그래프 저장소입니다. 서버를 띄우지 않고 디스크의 파일 하나로 돕니다.

**Neo4j.** 여러 사람이 같은 그래프를 볼 때 쓰는 그래프 데이터베이스입니다. 서버를 따로 띄워야 합니다.

## 비교 대상

**full-context.** 문서를 통째로 AI 모델에 넣어 답을 얻는 방식입니다. 문서가 많으면 비용과 시간이 급격히 늘고 애초에 다 들어가지 않습니다.

**chunk RAG.** 문서를 토막 내 두고 질문과 닮은 토막만 꺼내 쓰는 방식입니다. 닮은 조각은 잘 찾지만 조각끼리 이어져 있지 않습니다.

두 방식과의 비교는 [왜 그래프인가](/about/why-graph)에서 다룹니다.
