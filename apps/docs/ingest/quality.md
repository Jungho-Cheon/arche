# 추출이 빈약할 때

문서를 넣었는데 노드가 몇 개 안 나오거나, 질문에 "그래프에 없다"는 답만 돌아올 때 손볼 곳이에요. 답의 정확도를 가르는 건 모델 크기가 아니라 문서의 관계와 숫자를 얼마나 빠짐없이 그래프에 담았는지예요.

## 먼저 무엇이 들어갔는지 본다

추출이 문제인지 질문이 문제인지부터 갈라요.

```text
Arche 그래프에 어떤 종류의 노드가 몇 개나 있어?
```

REST 로는 이렇게 봐요.

```bash
curl "http://localhost:8000/schema"
```

**타입은 있는데 개수가 적으면** 추출이 부실한 거예요. 아래 hints 부터 보세요.

**찾던 대상이 아예 없으면** 그 문서가 안 들어갔을 수 있어요. 받는 확장자인지, 추출 모델이 그 형식을 다루는지 확인하세요. `claude-code/*` 추출은 글만 다뤄서 이미지와 PDF 의 이미지 페이지가 빠져요.

**개수는 넉넉한데 답이 안 나오면** 추출이 아니라 질문 쪽이에요. [그래프에 묻기](/query/)로 가세요.

## hints 로 추출을 보강한다

`hints` 는 추출할 때 함께 넘기는 짧은 메모예요. 도메인 용어 풀이나 강조할 대상을 적으면 모델이 그걸 참고해 노드와 관계를 뽑아요. **저장되는 원문은 바뀌지 않아요.** 추출 단계에만 쓰여요.

에이전트에게는 이렇게 시켜요.

```text
./docs/pricing.md 를 Arche 에 넣어줘.
힌트: SKU 는 상품 단위 코드, MOQ 는 최소 주문 수량. 상품과 가격 정책의 연결을 빠짐없이 뽑아줘.
```

효과가 좋은 hints 는 셋이에요.

- **약어와 사내 용어 풀이.** 문서에 설명 없이 나오는 말을 풀어 줘요.
- **뽑아야 할 대상 지목.** "표에 나오는 모든 금액과 기간을 노드로 뽑아줘" 처럼 놓치기 쉬운 것을 짚어요.
- **문서의 성격.** "이건 계약서고 조항마다 번호가 있다" 처럼 구조를 알려 줘요.

길이는 4000자까지예요.

::: warning 이미 넣은 문서에 hints 를 더해도 다시 뽑지 않아요
같은 출처의 같은 내용이 이미 성공적으로 적재돼 있으면, 다시 넣을 때 추출을 건너뛰어요. 내용과 추출기 버전만 보고 판단하므로 hints 를 새로 붙여도 마찬가지예요.

hints 를 반영하려면 그 출처가 적재되지 않은 상태에서 넣어야 해요. 그래프를 비우고 다시 넣는 게 가장 확실해요.

```bash
rm -rf arche_kuzu_db
```

먼저 작은 폴더에 `--dry-run` 으로 hints 효과를 확인한 뒤 본 적재에 적용하면 이 과정을 줄일 수 있어요.
:::

## 넣기 전에 가늠해 본다

`--dry-run` 은 추출만 하고 그래프에는 쓰지 않아요. hints 를 바꿔 가며 결과를 비교할 때 써요.

```bash
arche ingest ./docs/pricing.md --dry-run
```

추출 호출은 실제로 일어나므로 비용은 들어요. 파일 한둘로 좁혀서 돌리세요.

## 같은 대상이 여러 노드로 흩어졌을 때

한 회사나 한 정책이 문서마다 다른 이름으로 나와 따로 잡히면, 문서를 건너뛰는 질문이 끊겨요. "A 계약이 B 합의를 인용하고 그게 다시 기본 약관을 가리킨다" 같은 사슬이 여기서 무너져요.

Arche 는 적재할 때 기존 노드 후보를 추출 모델에 함께 넘겨 "이건 기존 X 와 같다"를 그 자리에서 판단하게 해요. 자동으로 안 잡힌 건 검토형 적재의 질문으로 올라와요.

그래서 **검토형 적재로 넣으면 CLI 보다 흩어짐이 덜해요.** 질문에 답하는 과정이 곧 합치는 작업이라서예요.

이미 흩어진 뒤라면 지금은 노드를 합치는 연산이 없어요. 그래프를 비우고 검토형 적재로 다시 넣는 쪽이 빨라요.

## 반대로 서로 다른 둘이 한 노드에 뭉쳤을 때

흩어짐의 반대예요. 이름이 닮았다는 이유로 "여름 프로모션"과 "여름 정산"이 한 점이 되면, 그 점을 지나는 모든 경로가 거짓이 돼요. 흩어짐은 답을 못 찾게 하지만 뭉침은 **틀린 답을 그럴듯하게** 만들어서 더 나빠요.

[노드 떼어내기](/ingest/split)로 둘로 가르세요. 어느 문서에서 나온 관계인지를 따라 자동으로 나누고, 갈리지 않는 것만 물어봐요.

## 문서가 너무 클 때

문서가 설정한 크기를 넘으면 여러 조각으로 나눠 추출해요. 기준은 `ARCHE_API_LLM_MODEL_CONTEXT_TOKENS` 이고 기본값은 128000 이에요.

조각을 나눠도 앞 조각의 내용을 함께 넘겨서 조각 경계에서 관계가 끊기지 않게 해요. 그래도 아주 긴 문서는 문단 단위로 나눠 넣는 편이 결과가 나아요.

## 추출 자체가 실패할 때

`extraction_failed` 가 나오면 AI 공급자의 응답을 읽지 못한 거예요. 같은 파일이 계속 실패하면 `--dry-run` 으로 그 파일만 돌려 좁혀요.

키나 크레딧 문제라면 공급자 메시지가 그대로 올라와요.

```text
insufficient_quota
```

폴더 적재에서는 한 파일이 실패해도 나머지는 계속 처리하고, 실패한 파일은 경고로 남아요.
