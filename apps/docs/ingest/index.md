# 문서를 그래프에 넣기

문서를 넣는 길은 셋입니다. 무엇을 넣는지와 사람이 확인할지에 따라 갈립니다.

| 길 | 넣는 단위 | 사람 검토 | 언제 |
| --- | --- | --- | --- |
| 검토형 적재 (MCP) | 파일 하나 또는 텍스트 하나 | 있음 | 에이전트로 넣고, 쓰기 전에 확인할 때 |
| CLI 적재 | 폴더 통째 | 없음 | 로컬 파일을 혼자 빠르게 넣을 때 |
| REST 적재 | 폴더 통째 | 없음 | 서버에 맡기고 진행을 지켜볼 때 |

셋 다 같은 추출 파이프라인을 씁니다. 결과 그래프의 품질은 같고, 다른 건 확인 절차와 넣는 단위입니다.

## 어떤 파일을 받나

받는 확장자는 `.txt`, `.md`, `.pdf`, `.jpg`, `.jpeg`, `.png`, `.webp` 입니다. PDF 는 페이지의 글과 페이지 안에 들어 있는 이미지를 함께 읽고, 이미지 파일은 그림 한 장에서 바로 노드와 관계를 뽑습니다.

::: warning 추출 모델에 따라 이미지가 빠집니다
추출을 `claude-code/*` 로 두면 글만 다루므로 이미지 파일과 PDF 의 이미지 페이지가 그래프에 들어가지 않습니다. Claude Code 플러그인의 기본값이 여기에 해당합니다. 이미지까지 넣으려면 [모델 갈아끼우기](/operate/models)에서 추출 모델을 바꾸세요.
:::

## 에이전트로 넣기 (검토형 적재)

에이전트가 `ingest_plan` 이나 `ingest_content` 로 계획을 세우고, `ingest_preview` 로 무엇이 바뀔지 보여 주고, 사람이 확인하면 `ingest_commit` 으로 확정합니다. 확정 전까지 그래프에는 아무것도 쓰이지 않습니다.

Claude Code 플러그인을 깔았다면 시키기만 하면 됩니다.

```text
./docs/refund-policy.md 를 Arche 에 넣어줘
```

**외부에서 읽어온 내용**은 임시 파일로 저장하지 말고 그대로 넘깁니다. 에이전트가 다른 도구로 Confluence 페이지나 웹 문서를 읽었다면 `ingest_content` 에 본문과 출처 라벨을 함께 줍니다.

```text
이 Confluence 페이지를 Arche 에 넣어줘
```

출처 라벨은 파일 경로를 대신해 같은 출처임을 알아보는 값입니다. `confluence:PAGE-123` 이나 문서 URL 처럼 그 출처를 계속 가리킬 값을 씁니다. **같은 페이지를 나중에 다시 넣을 때 같은 라벨을 써야** 갱신되고, 매번 다른 값을 주면 같은 내용이 중복으로 쌓입니다.

### 질문이 나왔을 때

미리 보기에 질문이 나오면, 새로 뽑은 노드가 기존 노드와 닮았지만 자동으로 합칠 만큼은 아니라는 뜻입니다. 각 질문은 새 이름과 후보 이름, 둘의 유사도를 함께 보여 줍니다.

같은 대상이면 합치고, 다른 대상이면 따로 둡니다. 판단이 서지 않으면 따로 두는 쪽이 안전합니다. 나중에 같다고 확인되면 다시 넣으면서 합칠 수 있지만, 잘못 합친 노드를 떼어내는 연산은 아직 없습니다.

### 폴더를 통째로 넣으려면

검토형 적재는 파일 하나씩만 돕니다. 폴더 전체를 넣으려면 파일마다 이 흐름을 반복하거나, 아래 CLI 적재를 쓰세요.

각 도구의 요청 필드와 응답 필드는 [적재 도구 참조표](/ingest/tools)에 있습니다.

## CLI 로 넣기

폴더를 재귀로 훑어 한 번에 넣습니다. 확인 절차가 없어 가장 빠릅니다.

```bash
arche ingest ./내문서폴더
```

파일마다 한 줄씩 찍고 마지막에 요약이 나옵니다.

```text
[1/3] /docs/pricing.md (2 chunks) ... 12e 9r in 3.4s
[2/3] /docs/policy.pdf ... 7e 5r in 2.1s
[3/3] /docs/diagram.png ... 4e 3r in 1.8s

ingest summary:
  files: 3 processed, 0 skipped (of 3 total)
  graph: +23 entities, +17 relations (chunks: 5)
```

`12e 9r` 은 그 파일에서 노드 12개와 관계 9개를 뽑았다는 뜻입니다.

**넣기 전에 가늠해 보려면** `--dry-run` 을 붙입니다. 추출만 하고 그래프에는 쓰지 않아서, 노드와 관계가 몇 개나 나올지 미리 볼 수 있습니다. 추출 호출은 실제로 일어나므로 비용은 듭니다.

```bash
arche ingest ./내문서폴더 --dry-run
```

**넣고 싶지 않은 폴더가 있으면** 맨 위에 `.archeignore` 를 두고 `.gitignore` 문법으로 적습니다. `node_modules`, `.venv`, `.git` 같은 환경 폴더와 점으로 시작하는 폴더는 적지 않아도 자동으로 빠집니다.

**같은 폴더를 다시 넣으면** 내용이 안 바뀐 파일은 다시 뽑지 않고 건너뜁니다. 요약에서 `processed` 가 0 이고 `skipped` 가 올라가는 건 정상입니다.

**한 파일이 실패해도** 그 파일만 건너뛰고 경고를 남긴 뒤 나머지를 계속 처리합니다. 깨진 PDF 하나 때문에 폴더 전체가 멈추지 않습니다.

## REST 로 넣기

API 서버에 맡기고 진행을 따로 물어봅니다. 오래 걸리는 적재를 띄워 두고 지켜볼 때 씁니다.

```bash
curl -X POST http://localhost:8000/admin/ingest \
  -H "Content-Type: application/json" \
  -d '{"directory_path": "/data/docs"}'
```

작업 번호를 바로 돌려주고 적재는 뒤에서 돕니다.

```json
{ "data": { "task_id": "01J8XR...", "status_url": "/admin/ingest/01J8XR.../status" } }
```

진행 상태를 물어봅니다.

```bash
curl http://localhost:8000/admin/ingest/01J8XR.../status
```

`state` 가 `running` 에서 `succeeded` 나 `failed` 로 바뀝니다.

::: warning 경로는 서버가 보는 경로입니다
`directory_path` 는 API 서버 안에서 보이는 경로여야 합니다. 서버를 컨테이너로 띄웠다면 내 노트북의 경로를 그대로 넣으면 안 됩니다. 없는 경로를 주면 `directory_not_found` 로 422 가 나오고 `details.hint` 에 원인이 담깁니다.
:::

작업 기록은 서버 프로세스 안에만 있습니다. 서버를 재시작하면 진행 상태를 더 물어볼 수 없습니다. 그래프에 이미 쓰인 내용은 남습니다.

## 넣은 뒤 확인

무엇이 들어갔는지는 그래프 모양을 보면 됩니다.

```bash
curl "http://localhost:8000/schema"
```

에이전트를 쓴다면 물어보는 쪽이 빠릅니다.

```text
Arche 그래프에 어떤 종류의 노드가 몇 개나 있어?
```

## 되돌리기

적재한 문서나 노드를 지우는 연산은 아직 없습니다. 되돌리려면 그래프 저장소를 통째로 비우고 다시 넣습니다.

임베디드 저장소라면 그래프 폴더를 지웁니다. 기본 경로는 명령을 실행한 자리의 `arche_kuzu_db` 입니다.

```bash
rm -rf arche_kuzu_db
```

원본 문서는 그대로 남습니다. Neo4j 를 쓴다면 데이터베이스를 비우는 쪽으로 처리합니다.
