# 문서를 그래프에 넣기

문서를 넣는 길은 셋이에요. 무엇을 넣는지와 사람이 확인할지에 따라 갈려요.

| 길 | 넣는 단위 | 사람 검토 | 언제 |
| --- | --- | --- | --- |
| 검토형 적재 (MCP) | 파일 하나 또는 텍스트 하나 | 있음 | 에이전트로 넣고, 쓰기 전에 확인할 때 |
| CLI 적재 | 폴더 통째 | 없음 | 로컬 파일을 혼자 빠르게 넣을 때 |
| REST 적재 | 폴더 통째 | 없음 | 서버에 맡기고 진행을 지켜볼 때 |

셋 다 같은 추출 파이프라인을 써요. 결과 그래프의 품질은 같고, 다른 건 확인 절차와 넣는 단위예요.

## 어떤 파일을 받나

받는 확장자는 `.txt`, `.md`, `.pdf`, `.jpg`, `.jpeg`, `.png`, `.webp` 예요. PDF 는 페이지의 글과 페이지 안에 들어 있는 이미지를 함께 읽고, 이미지 파일은 그림 한 장에서 바로 노드와 관계를 뽑아요.

::: warning 추출 모델에 따라 이미지가 빠져요
추출을 `claude-code/*` 로 두면 글만 다루므로 이미지 파일과 PDF 의 이미지 페이지가 그래프에 들어가지 않아요. Claude Code 플러그인의 기본값이 여기에 해당해요. 이미지까지 넣으려면 [모델 갈아끼우기](/operate/models)에서 추출 모델을 바꾸세요.
:::

## 에이전트로 넣기 (검토형 적재)

에이전트가 `ingest_plan` 이나 `ingest_content` 로 계획을 세우고, `ingest_preview` 로 무엇이 바뀔지 보여 주고, 사람이 확인하면 `ingest_commit` 으로 확정해요. 확정 전까지 그래프에는 아무것도 쓰이지 않아요.

Claude Code 플러그인을 깔았다면 시키기만 하면 돼요.

```text
./docs/refund-policy.md 를 Arche 에 넣어줘
```

**외부에서 읽어온 내용**은 임시 파일로 저장하지 말고 그대로 넘겨요. 에이전트가 다른 도구로 Confluence 페이지나 웹 문서를 읽었다면 `ingest_content` 에 본문과 출처 라벨을 함께 줘요.

```text
이 Confluence 페이지를 Arche 에 넣어줘
```

출처 라벨은 파일 경로를 대신해 같은 출처임을 알아보는 값이에요. `confluence:PAGE-123` 이나 문서 URL 처럼 그 출처를 계속 가리킬 값을 써요. **같은 페이지를 나중에 다시 넣을 때 같은 라벨을 써야** 갱신되고, 매번 다른 값을 주면 같은 내용이 중복으로 쌓여요.

### 질문이 나왔을 때

미리 보기에 질문이 나오면, 새로 뽑은 노드가 기존 노드와 닮았지만 자동으로 합칠 만큼은 아니라는 뜻이에요. 각 질문은 새 이름과 후보 이름, 둘의 유사도를 함께 보여 줘요. 이름이 글자 하나 안 틀리고 같은데 타입만 다를 때도 물어봐요.

**답하지 않으면 확정이 거부돼요.** 질문을 지나친 확정이 갈라 놓은 노드를 조용히 다시 만들기 때문이에요. 전부 따로 두는 게 맞다면 그렇다고 답하면 돼요 — 답을 안 하는 것과 "따로 둔다"고 답하는 것은 다르니까요.

같은 대상이면 합치고, 다른 대상이면 따로 둬요. 나중에 같다고 확인되면 다시 넣으면서 합쳐지고, 잘못 합쳤다면 [노드 떼어내기](/ingest/split)로 되돌려요. 양쪽 다 길이 있으니 여기서 오래 붙들지 마세요.

### 폴더를 통째로 넣으려면

검토형 적재는 파일 하나씩만 돌아요. 폴더 전체를 넣으려면 파일마다 이 흐름을 반복하거나, 아래 CLI 적재를 쓰세요.

각 도구의 요청 필드와 응답 필드는 [적재 도구 참조표](/ingest/tools)에 있어요.

## CLI 로 넣기

폴더를 재귀로 훑어 한 번에 넣어요. 확인 절차가 없어 가장 빨라요.

```bash
arche ingest ./내문서폴더
```

파일마다 한 줄씩 찍고 마지막에 요약이 나와요.

```text
[1/3] /docs/pricing.md (2 chunks) ... 12e 9r in 3.4s
[2/3] /docs/policy.pdf ... 7e 5r in 2.1s
[3/3] /docs/diagram.png ... 4e 3r in 1.8s

ingest summary:
  files: 3 processed, 0 skipped (of 3 total)
  graph: +23 entities, +17 relations (chunks: 5)
```

`12e 9r` 은 그 파일에서 노드 12개와 관계 9개를 뽑았다는 뜻이에요.

**넣기 전에 가늠해 보려면** `--dry-run` 을 붙여요. 추출만 하고 그래프에는 쓰지 않아서, 노드와 관계가 몇 개나 나올지 미리 볼 수 있어요. 추출 호출은 실제로 일어나므로 비용은 들어요.

```bash
arche ingest ./내문서폴더 --dry-run
```

**넣고 싶지 않은 폴더가 있으면** 맨 위에 `.archeignore` 를 두고 `.gitignore` 문법으로 적어요. `node_modules`, `.venv`, `.git` 같은 환경 폴더와 점으로 시작하는 폴더는 적지 않아도 자동으로 빠져요.

**같은 폴더를 다시 넣으면** 내용이 안 바뀐 파일은 다시 뽑지 않고 건너뛰어요. 요약에서 `processed` 가 0 이고 `skipped` 가 올라가는 건 정상이에요.

**한 파일이 실패해도** 그 파일만 건너뛰고 경고를 남긴 뒤 나머지를 계속 처리해요. 깨진 PDF 하나 때문에 폴더 전체가 멈추지 않아요.

## REST 로 넣기

API 서버에 맡기고 진행을 따로 물어봐요. 오래 걸리는 적재를 띄워 두고 지켜볼 때 써요.

```bash
curl -X POST http://localhost:8000/admin/ingest \
  -H "Content-Type: application/json" \
  -d '{"directory_path": "/data/docs"}'
```

작업 번호를 바로 돌려주고 적재는 뒤에서 돌아요.

```json
{ "data": { "task_id": "01J8XR...", "status_url": "/admin/ingest/01J8XR.../status" } }
```

진행 상태를 물어봐요.

```bash
curl http://localhost:8000/admin/ingest/01J8XR.../status
```

`state` 가 `running` 에서 `succeeded` 나 `failed` 로 바뀌어요.

::: warning 경로는 서버가 보는 경로예요
`directory_path` 는 API 서버 안에서 보이는 경로여야 해요. 서버를 컨테이너로 띄웠다면 내 노트북의 경로를 그대로 넣으면 안 돼요. 없는 경로를 주면 `directory_not_found` 로 422 가 나오고 `details.hint` 에 원인이 담겨요.
:::

작업 기록은 서버 프로세스 안에만 있어요. 서버를 재시작하면 진행 상태를 더 물어볼 수 없어요. 그래프에 이미 쓰인 내용은 남아요.

## 넣은 뒤 확인

무엇이 들어갔는지는 그래프 모양을 보면 돼요.

```bash
curl "http://localhost:8000/schema"
```

에이전트를 쓴다면 물어보는 쪽이 빨라요.

```text
Arche 그래프에 어떤 종류의 노드가 몇 개나 있어?
```

## 되돌리기

넣은 문서 하나를 걷어내려면 `ingest_delete` 에 그 출처를 줘요. 파일로 넣었으면 그 경로, `ingest_content` 로 넣었으면 그때 준 출처 라벨이에요.

```text
confluence:PAGE-123 으로 넣은 내용을 Arche 에서 빼줘
```

**다른 문서도 쓰는 노드는 안 지워져요.** 그 노드에서 이 출처만 떨어지고 남아요. 이 출처만 만든 노드는 붙어 있던 관계와 함께 사라져요.

적재와 같은 순서를 밟아요. 계획을 세우고, `ingest_preview` 로 무엇이 사라지는지 확인하고, `ingest_commit` 으로 확정해요. **되돌릴 수 없으니 미리 보기를 꼭 읽으세요.**

넣은 적 없는 출처를 주면 `invalid_input` 으로 거부해요. 출처 라벨을 정확히 기억하지 못하겠다면 노드 하나를 `get_entity` 로 열어 `source_refs` 를 보세요.

전부 지우고 처음부터 하려면 그래프 저장소를 비워요. 임베디드라면 폴더를 지우면 되고, 기본 경로는 명령을 실행한 자리의 `arche_kuzu_db` 예요.

```bash
rm -rf arche_kuzu_db
```

원본 문서는 그대로 남아요. Neo4j 를 쓴다면 데이터베이스를 비우는 쪽으로 처리해요.
