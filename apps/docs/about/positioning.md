# Arche 의 자리

Arche 는 답을 만들지 않아요. 그래프에서 사실 조각을 꺼내 주고, 그걸로 답을 쓰는 일은 부르는 쪽에 맡겨요.

## 무엇을 하고 무엇을 안 하나

| Arche 가 하는 일 | Arche 가 안 하는 일 |
| --- | --- |
| 문서에서 노드와 관계를 뽑아 저장 | 자연어 답변 생성 |
| 키워드로 출발점 찾기 | 어떤 조회를 몇 번 할지 정하기 |
| 그래프를 따라가는 조회 7가지 | 여러 조회 결과를 엮어 문장 만들기 |
| 같은 대상을 하나로 모으기 | 사용자 대화 관리 |

노출하는 건 원자적인 조회뿐이에요. 그 조각으로 답을 조립하는 건 에이전트의 몫이에요.

## 왜 답변 모델을 밖에 두나

측정에서 나온 결과 때문이에요. 같은 그래프인데도 한 번 묻고 마는 방식은 45.5%, 에이전트가 반복해서 조회하는 방식은 94-97% 였어요. 그래프 내용이 아니라 그걸 쓰는 방식이 정확도를 갈랐어요.

Arche 안에 답변 모델을 넣으면 그 반복 횟수와 순서를 Arche 가 정하게 돼요. 밖에 두면 부르는 쪽이 질문마다 다르게 조절해요. 그래서 밖에 뒀어요.

부수 효과로 모델을 갈아끼우기 쉬워졌어요. Arche 는 답을 안 만드니 어떤 모델이 답을 쓰든 상관하지 않아요.

수치의 근거는 [왜 그래프인가](/about/why-graph)에 있어요.

## 다른 방식과 나란히 놓으면

**문서를 통째로 모델에 넣기.** 문서가 적으면 가장 간단해요. 많아지면 비용과 시간이 늘고 애초에 다 안 들어가요. Arche 는 미리 지도를 만들어 두고 필요한 부분만 꺼내는 쪽이에요.

**토막 검색.** 문서를 잘라 두고 질문과 닮은 토막을 꺼내 쓰는 방식이에요. 표현이 비슷한 문단을 찾는 데는 이쪽이 나아요. 조각끼리 이어져 있지 않아 문서를 건너뛰는 질문에서 약해요. Arche 는 진입점을 찾을 때 같은 벡터 검색을 쓰지만, 거기서 멈추지 않고 관계를 따라가요.

**그래프 데이터베이스.** Neo4j 나 Kuzu 는 저장과 질의를 맡아요. 문서에서 무엇을 뽑을지, 같은 대상을 어떻게 합칠지는 다루지 않아요. Arche 는 그 위에서 그 부분을 맡고, 실제로 둘 중 하나를 저장소로 써요.

**검색 API.** 질문을 넣으면 답이 나오는 서비스와는 층이 달라요. Arche 는 그런 서비스를 만들 때 쓰는 부품이에요.

## 안에서 어떻게 나뉘나

```mermaid
flowchart LR
  DOC["문서<br>글, PDF, 이미지"]
  GRAPH["Arche 그래프<br>점(노드) + 선(관계)"]
  AGENT["AI 에이전트<br>답을 조립"]
  DOC -->|적재| GRAPH
  GRAPH -->|"조회 (MCP, REST)"| AGENT
```

**적재.** 폴더의 문서를 읽어 노드와 관계를 뽑아요. 다시 넣으면 바뀐 부분만 갱신해요.

**저장과 색인.** 그래프 저장소에 담고, 키워드로 출발점을 빨리 찾도록 어휘 검색과 벡터 검색 색인을 함께 만들어요.

**추출과 동일성 품질.** 같은 대상을 한 노드로 모으고, 숫자와 표를 빠뜨리지 않고, 잘못 뭉친 노드를 걸러내요. 정확도가 여기서 갈려요.

**조회 표면.** 같은 조회를 MCP 와 REST 두 통로로 내놓아요. 요청과 응답 스키마는 코드의 한 곳에서 나와서 두 통로가 어긋나지 않아요.

## 갈아끼울 수 있게 둔 곳

특정 기술에 묶이지 않도록 세 군데를 열어 뒀어요.

**부르는 쪽.** MCP 와 REST 두 표준 통로라 Claude 든 다른 모델이든 자체 에이전트든 연결할 수 있어요.

**저장소.** 임베디드 Kuzu 와 Neo4j 를 설정 한 줄로 바꿔요. 두 어댑터가 같은 기능을 노출해서 나머지 코드는 어느 쪽이 붙었는지 몰라요.

**추출과 임베딩 모델.** 모델 이름의 접두사만 바꾸면 갈아끼워요. OpenAI 없이 Claude 와 Voyage 로 돌릴 수도 있고, Claude Code 구독 인증으로 추출용 키 없이 돌릴 수도 있어요.
