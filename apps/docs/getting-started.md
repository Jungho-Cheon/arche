# 시작하기

문서 폴더 하나를 Arche 그래프에 넣고, Claude Code 에서 그 그래프로 질문에 답하는 데까지 한 번에 가 봐요. 끝나면 서버도 Docker 도 없이 내 문서가 관계 지도로 바뀐 상태가 돼요.

Claude Code 플러그인으로 진행해요. 다른 방식은 이 문서를 끝낸 뒤 [에이전트와 연결하기](/integrate/agent)에서 고르면 돼요.

준비물은 둘이에요.

- **uv** — 파이썬 도구를 받아 실행해요. 설치는 [docs.astral.sh/uv](https://docs.astral.sh/uv/) 를 보세요. Arche 실행 파일은 플러그인이 uv 로 알아서 받으므로 따로 설치할 게 없어요. **다만 uv 자체는 미리 있어야 해요.** 없으면 플러그인을 설치해도 도구가 안 올라와요. `uvx --version` 으로 확인하세요.
- **OpenAI API 키** — 글을 벡터로 바꾸는 데만 써요. 문서에서 노드와 관계를 뽑는 일은 이미 쓰고 있는 Claude Code 구독 인증이 맡아서 추가 비용이 거의 없어요. 키는 [platform.openai.com](https://platform.openai.com/api-keys) 에서 만들고, 결제 수단을 등록해 크레딧이 있어야 실제로 응답해요.

처음에는 파일 서너 개짜리 작은 폴더로 시작하세요.

## 1단계 — 플러그인 설치

Claude Code 를 열고 두 줄을 실행해요.

```text
/plugin marketplace add Jungho-Cheon/arche
/plugin install arche@arche
```

설치되면 `/arche-ingest` 와 `/arche-query` 두 명령이 생기고, Arche 도구 15개가 함께 올라와요. 도구가 보이는지는 대화창에서 확인할 수 있어요.

**처음 연결할 때 몇 초 걸려요.** uv 가 Arche 와 의존성을 받는 시간이에요. 그다음부터는 1 초 안쪽으로 떠요.

::: warning 이미지와 PDF 는 이 설정에서 빠져요
플러그인 기본값은 Claude Code 구독 인증으로 추출해요. 이 경로는 글만 다루므로 이미지 파일과 PDF 의 이미지 페이지는 그래프에 들어가지 않아요. 그래서 이 문서는 글 파일(`.md`, `.txt`)로 진행해요. 이미지까지 넣으려면 [모델 갈아끼우기](/operate/models)에서 추출 모델을 바꾸세요.
:::

## 2단계 — 임베딩 키 넣기

도구는 이미 붙었지만 문서를 넣으려면 임베딩 키가 있어야 해요. 터미널에서 한 번 넣어요.

```bash
uvx --from "arche-api @ git+https://github.com/Jungho-Cheon/arche.git@v0.1.2#subdirectory=apps/api" \
  arche config set-key
```

물어보면 키를 붙여 넣어요. 입력한 글자는 화면에 찍히지 않아요.

```text
OPENAI_API_KEY:
OPENAI_API_KEY 를 /Users/me/.config/arche/config.env 에 저장했습니다.
```

한 번 넣으면 터미널을 새로 열든 다른 폴더에서 실행하든 그대로 읽혀요. 파일은 소유자만 열 수 있게 잠겨요. **Claude Code 를 다시 켤 필요는 없어요.**

**명령이 길어서 거슬리면** 같은 것을 도구로 설치해 두면 `arche` 로 짧게 부를 수 있어요. 나중에 터미널에서 `arche ingest` 를 직접 쓸 생각이라면 어차피 이쪽이 편해요.

```bash
uv tool install "arche-api @ git+https://github.com/Jungho-Cheon/arche.git@v0.1.2#subdirectory=apps/api"
arche config set-key
```

**나중에 확인하고 싶으면** `arche config show` 를 실행해요. 키 값은 보여 주지 않고 설정됐는지만 알려 줘요.

## 3단계 — 문서 넣기

Claude Code 에서 폴더를 가리키며 시켜요.

```text
./내문서폴더 를 Arche 에 넣어줘
```

`arche-ingest` 스킬이 흐름을 잡아요. 파일마다 먼저 계획을 세우고, 무엇이 바뀔지 보여 준 다음, 확인을 받고서야 그래프에 써요.

보여 주는 내용은 이래요.

- 새로 만들 노드와 그 타입
- 기존 노드에 합칠 항목
- 새로 만들 관계
- 판단이 필요한 질문

**질문이 나오면** 새로 뽑은 노드가 기존 노드와 닮았지만 자동으로 합칠 만큼은 아니라는 뜻이에요. 같은 대상이면 합치고, 다른 대상이면 따로 둬요. 예를 들어 "환불 정책"과 "환불 규정"이 같은 문서를 가리키면 합치는 쪽이에요.

확인을 마치면 몇 개가 들어갔는지 알려 줘요.

그래프는 명령을 실행한 폴더 아래 `arche_kuzu_db` 에 쌓여요. 파일 하나가 아니라 폴더예요.

**처음부터 다시 하고 싶으면** 그 폴더를 지우면 돼요. 그래프만 사라지고 원본 문서는 그대로예요.

```bash
rm -rf arche_kuzu_db
```

## 4단계 — 물어보기

같은 대화창에서 방금 넣은 내용을 물어요.

```text
환불 규정이 어떤 조건에서 적용돼?
```

`arche-query` 스킬이 그래프를 짚어 가요. 먼저 질문의 핵심어로 출발점 노드를 찾고, 거기서 관계를 따라가며 필요한 사실을 모은 뒤 답을 써요.

답에는 어느 문서에서 온 사실인지가 함께 나와요. 노드마다 출처가 기록돼 있어서예요.

**"그래프에 없다"고 답하면** 정상이에요. 지어내지 않도록 규정해 둔 동작이에요. 두 가지를 확인하세요. 그 내용이 실제로 넣은 문서에 있는지, 그리고 질문에 쓴 낱말이 문서의 표현과 맞는지. 문서가 "반품"이라 쓰는데 "환불"로 물으면 출발점을 못 찾을 수 있어요.

**그래프에 뭐가 들어갔는지 보고 싶으면** 이렇게 물어보세요.

```text
Arche 그래프에 어떤 종류의 노드가 있어?
```

`get_schema` 를 불러 타입별 개수를 보여 줘요.

## 여기까지 하면

문서 폴더 하나가 관계 지도가 됐고, 에이전트가 그 지도를 짚어 답하는 한 바퀴를 돌았어요.

다음은 목적에 따라 갈려요.

- 외부 페이지나 다른 형식을 넣고 싶다면 [문서를 그래프에 넣기](/ingest/)로.
- 답이 부실하면 [추출이 빈약할 때](/ingest/quality)로.
- 팀과 같은 그래프를 보려면 [팀과 그래프 공유하기](/operate/sharing)로.
- Claude Code 가 아닌 에이전트와 연결하려면 [에이전트와 연결하기](/integrate/agent)로.
- 왜 이 방식이 더 정확한지 궁금하면 [왜 그래프인가](/about/why-graph)로.
