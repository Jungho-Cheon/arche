# 아키텍처 안에서 Arche 의 자리

"그래프로 문서를 다룬다"는 도구는 이미 여럿입니다. 그래서 Arche 를 자기 스택에 넣으려는 사람이 가장 먼저 던지는 물음은 둘입니다. **왜 다른 그래프 도구 대신 이걸 쓰지**, 그리고 **이 부품은 무엇을 책임지고 무엇을 안 하지**. 이 글은 그 둘에 답합니다. 앞은 설계 선택으로 견주고, 뒤는 인접 부품과의 책임 분담과 배치로 그립니다.

::: tip 비교의 결
아래 비교는 특정 제품의 기능 목록을 두고 우열을 매기려는 게 아닙니다. 각 도구가 어디에 무게를 실었는지, 그 설계 선택이 Arche 와 어떻게 갈리는지를 봅니다. 다른 도구의 세부 기능은 버전에 따라 바뀌므로, 여기서는 "설계 축" 수준으로만 다룹니다.
:::

## 다른 그래프 RAG 도구와 무엇이 다른가

RAG(retrieval-augmented generation)는 검색해 온 근거로 답을 생성하는 방식이고, 그래프 RAG 는 그 근거를 관계 그래프에서 찾는 갈래입니다. 이 갈래에는 Microsoft GraphRAG, LlamaIndex 의 PropertyGraphIndex, LightRAG, Zep 의 Graphiti, Neo4j 의 GraphRAG 패키지 등이 있습니다. Arche 는 이들과 세 축에서 갈립니다.

### 1. 답변을 만드는 LLM 이 어디에 있나

대부분의 그래프 RAG 도구는 "질문을 넣으면 답이 나오는" 파이프라인입니다. 검색과 답변 생성 LLM 이 도구 안에 함께 묶여 있죠. GraphRAG 의 local/global search 처럼, 도구가 그래프를 훑고 그 위에서 답까지 만들어 돌려줍니다.

Arche 는 답변 생성 LLM 을 **밖에 둡니다.** Arche 가 노출하는 건 원자적 그래프 조회 여섯 개(스키마 보기, 출발점 찾기, 이웃 펼치기, 경로 찾기 등)뿐이고, 그 조각으로 답을 조립하는 일은 부르는 쪽(에이전트)의 몫입니다([그래프에 질의하기](/guide/query)).

- **이 선택의 이점** — 호출하는 쪽이 자기 모델과 프롬프트, 에이전트 로직을 그대로 쓰면서 Arche 를 "관계 조회 계층"으로만 얹을 수 있습니다. 답변 품질과 정지 조건을 도구에 맡기지 않고 직접 통제합니다.
- **이 선택의 비용** — "질문 넣으면 답 나오는" 완성 검색을 기대한 팀에는 조립 부담이 넘어옵니다. 그래서 Arche 는 에이전트를 이미 굴리는 쪽에 잘 맞고, 단발 질의응답 상자를 원하는 쪽에는 과합니다.

### 2. 검색 인터페이스의 모양 — 조합형 대 한 방

경쟁군은 대체로 "한 방" 인터페이스입니다. `query(question)` 하나, 또는 local/global 두 모드로 검색을 감쌉니다. 내부에서 무엇을 어떻게 훑을지는 도구가 정합니다.

Arche 는 **원자적 조회를 조합**하게 합니다. 이웃 한 번 펼치고, 경로 한 번 잇고, 그 결과를 보고 다음 조회를 정하는 식입니다. 정확도가 여기서 나옵니다. 같은 그래프라도 한 번 검색하고 바로 답할 때(45.5%)보다, 에이전트가 조회를 여러 번 던지며 좁혀 갈 때(94-97%) 정답률이 크게 뛰었습니다([왜 그래프인가](/concepts/why-graph)).

- **이점** — 에이전트가 탐색 예산을 스스로 조절하고, 근거가 약한 경로(높은 `hub_score`)를 걸러 낼 수 있습니다.
- **비용** — "한 방 검색"을 기대한 통합자에게는 배울 게 있습니다. 그 배움을 줄이려고 [코드로 에이전트에 붙이기](/guide/programmatic-integration)에 조합 예제를 둡니다.

### 3. 문서 사이의 같은 대상을 합치나

이게 Arche 가 가장 세게 미는 축입니다. 같은 회사나 단백질이 여러 문서에 따로 등장할 때 이를 한 점으로 합쳐야 문서를 건너뛰는 사슬이 이어집니다. 측정에서 이 문서 간 합치기의 유무가 정답률 격차의 핵심이었습니다(생물의학 평가셋에서 비교 대상은 문서를 가로지르는 선이 0.2%뿐이라 문서마다 고립된 섬이 됐고, Arche 는 12%를 여러 문서에 걸쳐 합쳤습니다. [왜 그래프인가](/concepts/why-graph)). 문서 단위로 그래프를 만들고 끝내는 도구와, 문서 경계를 넘어 대상을 하나로 모으는 Arche 가 여기서 갈립니다.

## 이 부품은 무엇을 책임지고 무엇을 안 하나

Arche 를 스택에 넣으려면 인접 부품과의 책임 경계를 그려야 합니다. 아래 표가 그 분담입니다.

| 인접 부품 | 누가 소유하나 | Arche 는 무엇을 가정하나 |
| --- | --- | --- |
| 답변 생성 LLM | 호출하는 쪽 | 관여하지 않음. Arche 는 그래프 조각만 돌려주고 답은 부르는 쪽이 조립 |
| 추출·임베딩 LLM | Arche 가 호출 | provider 를 환경 변수로 교체([모델 갈아끼우기](/guide/models)). 적재하는 문서 내용이 이 공급자로 전송됨 |
| 벡터 인덱스 | Neo4j 내장 | 별도 벡터 DB 를 두지 않음. Neo4j 5.11+ 의 벡터 인덱스를 진입점 검색에 사용 |
| 그래프 저장소 | 호출하는 쪽이 호스팅하는 Neo4j | Arche 는 자기 Neo4j 에 붙어 읽고 씀. 데이터는 그 Neo4j 에 남음 |
| 인증·권한 게이트웨이 | 호출하는 쪽(앞단 프록시) | Arche 는 자체 인증이 없음. `ns:` 헤더를 라우팅 힌트로만 읽음([앞단 인증 통합 패턴](/guide/namespace#앞단-인증으로-칸을-강제하기)) |
| 에이전트 오케스트레이션·정지 조건 | 호출하는 쪽 | 언제 멈추고 어떻게 엮을지는 부르는 에이전트가 결정([에이전트에 연결하기](/guide/agent-integration)) |

## 배치로 보면

한 요청이 흐르는 길을 상자로 그리면 이렇습니다.

```
  사용자 질문
     │
     ▼
 ┌──────────────┐   도구 호출(MCP/REST)   ┌───────────┐
 │  에이전트     │ ──────────────────────▶ │  인증      │
 │ (+ 답변 LLM) │ ◀────────────────────── │  프록시    │   ← 인증·namespace 강제
 └──────────────┘   그래프 조각(점·선)      └─────┬─────┘
     │                                          │
     │ 답 조립                                   ▼
     ▼                                    ┌───────────┐   추출·임베딩   ┌──────────────┐
  사람에게                                 │  Arche    │ ────────────▶ │ 추출·임베딩   │
                                          │  (조회+적재)│               │ LLM 공급자    │
                                          └─────┬─────┘               └──────────────┘
                                                │ 읽기·쓰기
                                                ▼
                                          ┌───────────┐
                                          │  Neo4j    │  ← 그래프 + 벡터 인덱스
                                          └───────────┘
```

[소개](/intro)의 단순한 그림(흩어진 문서 → Arche → 에이전트)이 처음 감을 잡는 용이라면, 위 그림은 실제로 배치할 때 챙겨야 할 상자를 모두 드러낸 것입니다. 답변 LLM 은 에이전트 쪽에 있고, 추출·임베딩 LLM 은 Arche 가 부르며, 인증은 앞단 프록시가 맡습니다.

## 정직한 한계

- 위 비교는 설계 축 수준입니다. 각 도구의 정확한 기능은 버전에 따라 바뀌므로, 채택 전에 대상 도구의 최신 문서로 확인하세요.
- 정답률 수치(94-97% 등)는 작은 공개 평가셋에서 비교 대상 하나(graphify)를 상대로 잰 초기 신호입니다. 규모·비용은 아직 공개 수치가 없습니다([왜 그래프인가](/concepts/why-graph)의 "정직한 한계").
