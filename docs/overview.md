# Arche — 프로젝트 소개

> 이 문서는 Arche 를 처음 보는 사람을 위한 것이다. 전문 용어는 처음 나올 때
> 한 줄로 풀어 쓴다. 코드를 몰라도 "무엇을 만드는가 / 왜 필요한가 / 어떤 가치가
> 있는가 / 무엇으로 이루어져 있는가" 를 따라갈 수 있게 했다.

## 한 문장

**Arche 는 흩어진 문서 더미를 "관계 지도(그래프)" 로 바꿔, AI 에이전트가
적은 비용으로 정확한 답을 찾게 돕는 도구다.**

여기서 용어 둘만 먼저 풀면:
- **AI 에이전트** — 사람의 질문을 받아 스스로 도구를 호출해가며 답을 만드는 AI
  프로그램 (예: Claude, GPT 기반 비서).
- **그래프 (graph)** — 점(엔티티)과 점을 잇는 선(관계) 으로 지식을 표현한 것.
  "쿠폰 X" 라는 점과 "상품 A" 라는 점을 "적용된다" 라는 선으로 잇는 식.

---

## 1. 어떤 문제를 푸는가

회사에는 정책 문서, 보고서, 매뉴얼, 계약서가 수백 개씩 흩어져 있다. AI 에게
"이 규칙이 어떤 상품에 적용되고, 그게 작년 정책과 어떻게 다른가?" 를 물으면, AI 는
그 답을 *여러 문서에 걸쳐* 조각조각 모아야 한다. 지금 흔한 두 방법은 각각 약점이
있다.

| 방법 | 하는 일 | 약점 |
|---|---|---|
| **문서 전체를 AI 에 통째로 넣기** (full-context) | 모든 문서를 프롬프트에 붙여 한꺼번에 읽힌다 | 토큰(=처리량) 비용이 폭증하고 느리다. 문서가 많으면 아예 다 들어가지 못한다. |
| **청크 벡터 검색** (chunk RAG) | 문서를 토막 내 비슷한 토막만 찾아 AI 에 건넨다 | 토막끼리의 *관계* 를 잇지 못한다. "A→B→C" 처럼 여러 문서를 건너뛰며 따라가는 질문, 표 속 숫자 비교에 약하다. |

> **용어:** **RAG (Retrieval-Augmented Generation, 검색 보강 생성)** — AI 가 답하기
> 전에 관련 문서를 먼저 검색해 참고하는 방식. **토큰(token)** — AI 가 글을 처리하는
> 최소 단위로, 많을수록 비용과 시간이 든다.

핵심 문제는 **"여러 문서에 흩어진 관계"** 다. 청크 검색은 비슷한 *내용* 은 잘 찾지만
"이것이 저것을 대체한다", "이 회사의 이 수치가 저 수치보다 크다" 같은 *연결* 은
놓친다. 이 연결이 바로 어려운 질문의 정답이 사는 곳이다.

---

## 2. Arche 의 접근

Arche 는 문서를 미리 **관계 지도(그래프)** 로 바꿔 둔다. 그리고 AI 에이전트가
그 지도 위에서 **작고 값싼 조회 동작** 만으로 필요한 부분을 따라가게 한다.

비유하면, 도시 전체 지리를 통째로 외우게 하는(full-context) 대신, 또는 비슷한
거리 사진만 잔뜩 보여주는(청크 검색) 대신, **지하철 노선도와 "한 정거장씩 이동"
버튼** 을 쥐여 주는 것이다. 에이전트는 출발점을 찾고, 이웃 역을 보고, 두 역
사이 경로를 묻는 식으로 답에 필요한 만큼만 짚어 간다.

이 "작고 값싼 조회 동작" 을 **그래프 프리미티브 (graph primitive)** 라 부른다.
여섯 가지다.

| 프리미티브 | 하는 일 (쉽게) |
|---|---|
| `get_schema` | 이 그래프에 어떤 종류의 점과 선이 있는지 개요를 본다. |
| `find_entities` | 키워드로 출발점(점)을 찾는다. |
| `get_entity` | 점 하나의 상세와 몇 개와 연결됐는지 본다. |
| `get_neighbors` | 한 점의 이웃들을 펼친다. |
| `find_path` | 두 점 사이를 잇는 경로(연결 사슬)를 찾는다. |
| `get_subgraph` | 여러 출발점 주변을 한꺼번에 펼친다. |

중요한 설계 선택: **Arche 는 "답을 쓰지" 않는다.** 자연어로 답을 만드는 일은
에이전트(또는 부르는 쪽)의 몫이고, Arche 는 *원자적인 그래프 조회* 만
제공한다. 그래서 답을 만드는 AI 모델을 무엇으로든 갈아 끼울 수 있다.

## 3. 핵심 가치 — 검증된 것

이 접근이 말로만 좋은 게 아니라 **측정으로 확인됐다** (같은 AI 모델로 공정 비교).

- **다중 문서와 수치 질문에서 청크 검색을 크게 앞선다.** 공개 벤치마크(여러
  회사 재무 보고서를 가로지르는 질문 모음, FinanceBench)에서 에이전트가
  그래프만으로 답했을 때 **94-97%**, 같은 조건의 대표적 청크 검색 도구는
  **57.6%** 였다. 생물의학 다중 추론(MedHop)에서도 우위. 근거 — `docs/adr/`
  의 ADR-0016.
- **정답의 레버는 "모델 크기" 가 아니라 "추출 완전성" 이다.** 더 큰 모델로
  바꾸는 것보다, *문서에서 관계와 숫자를 빠짐없이 뽑아 그래프에 담는 것* 이
  정확도를 올렸다 (ADR-0016/0017). 그래서 Arche 는 숫자, 표, 식별자를 놓치지
  않는 추출 규칙에 공을 들인다.
- **싸고 빠르다.** 통째로 넣기(full-context)에 비해 토큰과 시간 비용이 훨씬 낮으면서
  정확도는 견준다. "정확도 대 비용" 두 축에서 두 방법 모두보다 유리한 위치에 선다
  (가치 명제 상세 — `docs/prd/1_mvp.md`, ADR-0001).

> **솔직한 한계:** 정답률의 *절대값* 은 도메인마다 다르다 (위 재무 질문은 90%대,
> 생물의학 질문은 30%대). 변하지 않는 것은 *순위* — 같은 조건에서 청크 검색보다
> 앞선다는 점이고, 절대 정답률은 "그래프에 얼마나 빠짐없이 담았는가" 에 달렸다
> (한계까지 명시한 근거는 ADR-0016).

> **용어:** **벤치마크(benchmark)** — 도구 성능을 공정하게 비교하기 위한 표준
> 문제 모음. **ADR (Architecture Decision Record, 의사결정 기록)** — "왜 이렇게
> 결정했는가" 를 남긴 문서. `docs/adr/` 에 번호순으로 있다.

### 교체 가능하게 설계됨 (agnostic)

먼저 짚어 둘 것 — Arche 에는 AI 가 두 자리에서 쓰인다. (1) 그래프를 **만들 때**
문서에서 점과 선을 뽑는 AI(추출용 LLM), (2) 그래프를 **쓸 때** 질문에 답하는 AI(소비
에이전트). 둘은 별개다. 이 둘을 포함해, 특정 기술에 묶이지 않도록 세 축 모두 열어
뒀다 (ADR-0018).

- **어떤 소비 에이전트든** — 두 표준 통로(아래 4절의 REST, MCP)로 노출하므로 Claude,
  GPT, 자체 에이전트 누구나 붙는다.
- **어떤 그래프 DB 든** — 저장소를 능력별 인터페이스 뒤에 두어 교체 가능.
- **어떤 추출 LLM/임베딩이든** — 문서에서 점과 선을 뽑는 AI 모델, 노드를 임베딩하는
  모델 모두 인터페이스로 분리했다. 지금은 추출에 OpenAI, Anthropic(Claude),
  Claude Code(`claude -p`), 임베딩에 OpenAI 와 Voyage 가 들어 있고, 환경 변수의 모델
  이름 접두사만 바꾸면(`openai/...`, `anthropic/...`, `claude-code/...`, `voyage/...`)
  코드 수정 없이 갈아끼운다 — OpenAI 없이 Claude + Voyage 로, 또는 설치된 Claude Code
  구독 인증을 쓰는 `claude-code/...`(별도 API 키 불필요, 텍스트 전용)로도 돌릴 수 있다
  (ADR-0019).

## 4. 구성요소 (한눈에)

```
   문서 더미                  Arche                       AI 에이전트
 (md/pdf/이미지)                                              (질문하는 쪽)
      │                ┌──────────────────────────┐
      │   ① 적재        │  ② 그래프 저장            │   ④ 두 통로로 질의
      └───────────────▶│   점(엔티티)+선(관계)     │◀───── MCP (AI 도구 표준)
                       │   + 진입점 검색 인덱스     │◀───── REST API (HTTP)
                       └────────────┬─────────────┘
                                    │ ③ 품질 (추출 완전성과 동일성)
                                    ▼
                       정확하고 끊김 없는 관계 지도
```

| # | 구성요소 | 쉽게 말하면 |
|---|---|---|
| ① | **적재 파이프라인 (ingest)** | 폴더의 문서들(글, PDF, 이미지)을 읽어 점과 선을 뽑아 그래프에 넣는다. 같은 파일을 다시 넣으면 바뀐 부분만 갱신(델타). |
| ② | **그래프 저장소 + 진입점 검색** | 점과 선을 그래프 DB 에 저장 (기본은 서버 없는 임베디드 Kuzu, 팀 공유가 필요하면 Neo4j). 키워드로 출발점을 빠르게 찾도록 어휘 검색 + 의미(벡터) 검색을 함께 쓴다. |
| ③ | **추출과 동일성 품질** | "같은 대상" 을 한 점으로 모으고(예: 정식 명칭과 약어, 코드를 한 점으로), 숫자와 표를 빠짐없이 보존하며, 잘못 뭉친 점을 걸러낸다. 정확도의 핵심 레버. |
| ④ | **프리미티브 표면 (REST + MCP)** | 6가지 조회 동작을 두 표준 통로로 노출. 에이전트는 이것만 조합해 답을 찾는다. |
| ⑤ | **평가 하베스 (eval)** | 위 가치를 *증명* 하는 측정 장치. 같은 질문을 여러 방법으로 풀어 정확도와 비용을 비교한다. |

> **용어:** **REST API** — 프로그램끼리 HTTP 로 주고받는 표준 방식. **MCP (Model
> Context Protocol)** — AI 에이전트가 외부 도구를 호출하는 표준 규약. 둘은 *같은*
> 6가지 동작을 노출한다 (한쪽만 쓰는 에이전트도 동일하게 쓸 수 있도록).
> **그래프 DB** — 점과 선 구조를 잘 다루는 데이터베이스. Arche 는 기본으로 서버가
> 필요 없는 임베디드 Kuzu 를 쓰고, 팀이 그래프를 공유할 때는 Neo4j 로 바꾼다.

## 5. 한 번의 질문이 흐르는 모습

> 질문: "쿠폰 X 가 적용되는 상품이, 작년에 단종된 상품 라인과 관련이 있나?"

1. 에이전트가 `find_entities("쿠폰 X")` 로 출발점을 찾는다.
2. `get_neighbors` 로 쿠폰 X 가 적용되는 상품들을 펼친다.
3. `find_path` 로 그 상품과 "단종된 상품 라인" 사이 연결 사슬을 찾는다.
4. 돌아온 작은 부분 그래프(점과 선 몇 개)만 읽고 답을 구성한다.

문서 전체를 읽지 않고, 비슷한 토막을 헤매지도 않고, **필요한 연결만** 몇 번의 값싼
조회로 짚었다. 이것이 Arche 가 노리는 그림이다.

## 6. 직접 해보기 (약 5-10분)

> 준비물: **Python 3.12** 와 **AI 모델 API 키** 하나 (임베딩용). 기본은 서버 없이
> 도는 임베디드 그래프라 Docker 가 필요 없다. 추출은 OpenAI 대신 설치된 Claude
> Code 의 구독 인증(별도 키 없이)이나 Anthropic 으로도 돌릴 수 있다 — 모델 접두사만
> 바꾸면 된다 (아래 .env 주석 참고, ADR-0019). 처음엔 파일 몇 개짜리 작은 폴더로
> 시작하길 권한다 — 적재할 때 문서마다 모델 호출이 일어나 비용이 든다.

```bash
# 1) 내려받고 키 채우기 (Docker 불필요 — 기본은 서버 없는 임베디드 그래프)
git clone https://github.com/Jungho-Cheon/arche.git
cd arche
cp .env.example .env          # .env 에 OPENAI_API_KEY 를 채운다 (임베딩에 필요)

# 2) 내 문서 폴더(.md / .txt / .pdf / 이미지)를 그래프로 적재 — 임베디드 Kuzu 파일에 바로 저장
uv run --project apps/api arche ingest ./내문서폴더

# 3) 질의 — 에이전트(Claude Desktop / Cursor 등)에 MCP 도구로 연결한다
uv run --project apps/api arche mcp serve --stdio

# 팀에서 같은 그래프를 공유하려면(선택): docker compose 로 Neo4j + API 서버를 띄우고
# ARCHE_API_GRAPH_BACKEND=neo4j 로 바꾼다. 그러면 :8000/docs 에서 REST 도 쓸 수 있다.
```

MCP 클라이언트(예: Claude Desktop)의 설정 파일에는 이렇게 등록한다.

```json
{ "mcpServers": { "arche": { "command": "arche", "args": ["mcp", "serve", "--stdio"] } } }
```

> 막히면 개발자용 [`apps/api/ARCHITECTURE.md`](../apps/api/ARCHITECTURE.md) 의 "빠른 시작"
> 과 저장소 루트의 README 를 함께 보면 된다. (`uv` 는 파이썬 패키지 매니저로, 위
> `uv run` 명령이 필요한 의존성을 자동으로 설치한다.)

## 7. 지금 상태와 앞으로

- **지금 (MVP — Minimum Viable Product, 핵심만 갖춘 최소 동작 버전):** 백엔드(`apps/api`) — 적재 + 그래프 + 6 프리미티브(REST + MCP) 가
  동작한다. 가치를 증명하는 평가 장치(`eval/`)도 있다.
- **앞으로 (post-MVP):** 소개와 API 문서 사이트(`apps/docs`), 그리고 기업용 웹
  화면(`apps/web-ui`, 로그인 + 워크스페이스별 그래프 조회). 단일 저장소(monorepo)
  구조로 이들이 깨끗이 들어올 자리를 잡아 뒀다 (ADR-0018).
