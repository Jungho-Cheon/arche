# ADR-0023: 임베디드 기본, 공유 서버가 목적지 — 보존해야 할 이음매 계약

Status: accepted
Date: 2026-07-19

## TL;DR

Arche 는 지금 **한 사람이 자기 컴퓨터에서 서버 없이 바로 쓰는** 형태를 기본으로 한다. 그래프(점과 선으로 된 지식 지도)를 파일 하나에 담는 임베디드 데이터베이스(Kuzu)를 기본 저장소로 쓰고, 별도의 서버 프로세스를 띄우지 않는다. 그런데 Arche 가 궁극적으로 가려는 곳은 **사내 구성원이 같은 그래프를 함께 보는 공유 세컨드브레인**이다.

이 ADR 은 그 둘이 충돌하지 않음을 못박는다. 임베디드를 기본으로 두는 건 공유를 포기하는 게 아니라 순서의 문제다. 같은 코어가 두 가지 배치(개인 임베디드, 팀 공유 서버)를 모두 떠받치고, 공유로 가는 길은 **세 개의 이음매(seam)를 깨지 않는 것**으로 열어 둔다. 서버 배포와 인증은 지금 만들지 않고 뒤로 미루되, 그건 길을 닫는 게 아니라 나중에 여는 것이다.

> **임베디드(embedded) 데이터베이스** — 별도 서버 없이 프로그램에 라이브러리로 딸려 들어가 파일에 저장하는 DB. SQLite 를 떠올리면 된다. Arche 는 Kuzu 를 쓴다.
>
> **토폴로지(topology)** — 시스템 조각들이 어떻게 배치되고 연결되는지의 그림. 여기서는 "개인 임베디드" 배치와 "팀 공유 서버" 배치 두 가지를 가리킨다.
>
> **이음매(seam)** — 나중에 구조를 바꿔 끼울 수 있도록 코드에 미리 그어 둔 경계선. 이 경계를 지켜 두면 저장소나 전송 방식을 갈아 끼워도 나머지 코드가 안 바뀐다.
>
> **MCP (Model Context Protocol)** — AI 에이전트가 외부 도구를 호출하는 표준 규약. Arche 는 이걸로 도구를 노출한다.

## 이 ADR 을 읽는 이유

- Arche 를 개인용으로 쓰다가 팀에서 공유하려 할 때 무엇이 바뀌고 무엇이 그대로인지 알고 싶다면.
- "임베디드를 기본으로 정했으니 공유는 접은 것 아닌가" 라는 오해를 풀고 싶다면.
- 앞으로 어떤 코드 변경이 공유 경로를 깨뜨리는지(그래서 피해야 하는지) 알고 싶다면.

## 배경 — 하나의 코어, 두 토폴로지

Arche 의 정체성은 AI 에이전트가 접근하는 세컨드브레인이다. 에이전트는 사용자의 컴퓨터에서 돌고, 지식은 개인이나 팀의 것이며, 설치하자마자 쓸 수 있어야 가치가 산다. 그래서 기본 배치는 이렇다.

```
토폴로지 1 (기본, 개인/에이전트) — 도커도 클라우드도 없음
  [Claude Code + Plugin] --spawn--> [arche stdio MCP] --> [Kuzu 파일]
```

여기서 "서버" 는 클라우드에 상주하는 프로세스가 아니라 플러그인이 세션마다 띄우는 로컬 프로세스다. 네트워크가 없고 저장소는 디스크의 파일 하나다.

반면 여러 사람이 같은 그래프를 함께 보려면 배치가 달라진다.

```
토폴로지 2 (팀 공유, opt-in) — 서버 + 공유 DB
  [Claude Code + Plugin] --HTTP MCP--> [arche 서버] --> [Neo4j (공유 DB)]
```

이 두 배치는 **배타 관계가 아니라 같은 코어의 두 모습**이다. 스위치는 플러그인 설정 한 줄(`stdio` 냐 `url` 이냐)과 저장소 백엔드 플래그(`ARCHE_API_GRAPH_BACKEND`)다.

## 결정

### 1. 목적지는 공유 세컨드브레인 (ADR-0015 재확인)

사내 구성원이 같은 그래프를 함께 보는 형태가 Arche 가 가려는 곳이다. ADR-0015 가 정의한 공유 운영 모델을 목적지로 재확인한다.

### 2. 기본 진입 토폴로지는 임베디드 (ADR-0020 재확인)

개인이 설치하자마자 쓰는 경로는 임베디드 Kuzu 다. ADR-0020 의 투 트랙 저장소(임베디드 Kuzu 기본, Neo4j 는 선택)를 기본값으로 재확인한다. 문서(README, overview, `.env.example`)도 임베디드를 기본으로, Neo4j 를 팀 공유용 선택지로 배치한다.

### 3. 보존해야 할 이음매 — 앞으로 어떤 작업도 깨면 안 됨

공유 경로가 열려 있으려면 세 이음매를 지켜야 한다. 이건 이미 코드에 있고(각각 어댑터/도메인/전송 계층에 존재), 앞으로도 유지한다.

- **GraphRepository 포트** — 도메인 코드가 저장소가 Kuzu 인지 Neo4j 인지 몰라야 한다. 저장소 선택은 팩토리(`build_graph_repository`)가 플래그로만 한다 (ADR-0018 능력별 포트).
- **`namespace_id` 테넌시 축** — 어느 데이터가 누구/어느 팀의 것인지 가르는 축. 지금도 도메인 전반을 관통한다. 공유가 되려면 이 격리가 필수라 제거하거나 우회하면 안 된다.
- **교체 가능한 MCP 전송** — stdio(로컬)와 HTTP(네트워크) 두 전송을 모두 지원한다. 한쪽으로 못박지 않는다.

> **테넌시(tenancy)** — 한 시스템을 여러 사용자/팀이 나눠 쓸 때 각자의 데이터를 서로 안 보이게 가르는 것. `namespace_id` 가 그 경계다.

### 4. 지금은 미룸 — 닫는 게 아니라 나중에 여는 것

다음은 지금 만들지 않는다. 공유 경로를 닫는 게 아니라, 필요해질 때(팀 공유가 실제로 요구될 때) 여는 성장 항목이다.

- 배포용 서버 이미지(도커 이미지 빌드/레지스트리/배포 가이드).
- 인증/인가와 사내 SSO(Single Sign-On, 사내 계정으로 한 번 로그인해 여러 서비스를 쓰는 방식) 통합.
- 어드민 콘솔(그래프를 눈으로 보고 손보는 관리 화면).

## 결과

- 개인 사용자는 지금 임베디드로 바로 테스트할 수 있다. 서버도 클라우드도 필요 없다.
- 팀 공유는 코드가 이미 떠받친다 — Neo4j 어댑터, HTTP MCP 전송, `namespace_id` 격리가 모두 존재한다. 임베디드를 기본으로 둔 건 플래그와 설정 한 줄의 차이지 구조를 도려낸 게 아니다.
- 앞으로의 작업은 위 세 이음매를 깨지 않아야 한다. 예를 들어 도메인이 임베디드 단일 작성자를 전제하거나, `namespace_id` 를 빼거나, MCP 를 stdio 전용으로 박으면 공유 경로가 닫힌다.
- 서버 배포와 인증은 별도 후속 결정으로 남긴다. 그때 이 ADR 이 목적지와 이음매를 이미 정해 둔 출발점이 된다.
