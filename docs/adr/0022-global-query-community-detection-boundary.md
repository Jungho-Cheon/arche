# ADR-0022: 전역/주제 질문 지원 경계 — 커뮤니티 탐지-only 방향 확정, MVP 미지원

Status: accepted
Date: 2026-07-19

## TL;DR

Arche 프리미티브는 엔티티 하나에서 출발해 주변을 훑는 **지역(local) 질문** 에 강하다. 반면 "이 코퍼스 전체를 관통하는 주제/패턴은?" 같은 **전역(global) 질문** 에는 약하다. 이건 버그가 아니라 설계 선택이다 — ADR-0016 이 답변 생성 LLM 을 Arche 밖에 두기로 했으므로 Arche 는 사전 생성 요약을 만들지 않는다.

이 ADR 은 **경계를 긋는 결정** 이다. (1) 전역/주제 질문은 **MVP 에서 지원하지 않는다** — 새 프리미티브를 지금 노출하지 않는다. (2) 다만 나중에 지원하게 될 때의 형태를 **커뮤니티 탐지-only** 로 못박는다 — 어떤 노드가 한 군집인지의 **구조 정보만** 프리미티브로 주고, 요약문은 에이전트가 회수한 서브그래프로 직접 만든다. (3) GraphRAG 식 **커뮤니티 요약 사전 생성** 은 ADR-0016(답변 외부화) 정면 위반이라 **선택지에서 영구 제외** 한다.

> **지역(local) 질문 vs 전역(global) 질문** — 지역은 "이 상품의 반품 규칙은?" 처럼 한 지점에서 출발해 이웃을 훑으면 답이 나온다. 전역은 "정책 전체의 큰 주제는?" 처럼 출발점이 없고 그래프 전체를 위에서 내려다봐야 답이 나온다.
>
> **커뮤니티(community)** — 서로 촘촘히 연결된 노드 덩어리. 상거래 그래프라면 배송 관련 노드 한 덩어리, 환불/교환 한 덩어리처럼 자연히 묶이는 군집이다. 이 군집을 찾는 게 **커뮤니티 탐지** 다.
>
> **Leiden** — 커뮤니티 탐지 알고리즘의 하나. Microsoft GraphRAG 가 이 알고리즘으로 군집을 찾고 군집마다 요약을 미리 써서 전역 질문에 답한다. 알고리즘 선택 자체는 지원이 확정될 때 후속 이슈에서 정한다.

## 이 ADR 을 읽는 이유

- Arche 가 전역/주제 질문을 어디까지 다루는지, 그 경계가 어디인지 알고 싶다면
- "왜 GraphRAG 처럼 커뮤니티 요약을 미리 만들지 않는가" 가 궁금하다면
- 전역 질문을 나중에 지원하게 될 때 어떤 형태로 열릴지(요약이 아니라 탐지-only) 미리 확인하려면

## 읽기 전 권장 배경

- [ADR-0016 — 에이전트 반복 graph-only + 정량 추출](./0016-agentic-graphonly-and-quantitative-extraction.md) — 답변 생성 LLM 을 Arche 밖에 둔다는 원칙. 본 ADR 이 전역 질문에서도 이 원칙을 지키는 근거다.
- [ADR-0006 — MCP/REST 표면](./0006-mcp-rest-primitives-surface.md) — 원자적 그래프 프리미티브만 노출하고 자연어를 받지 않는다. 커뮤니티 탐지를 프리미티브로 더하는 것은 이 표면에 대한 결정이다.

## Context — 왜 이 결정이 필요했나

### 전역 질문에 약한 이유

Arche 의 프리미티브(get_neighbors, find_path, get_subgraph 등)는 앵커 노드에서 출발하는 구조 순회다. 이 모양은 지역 질문에 최적이다. 전역 질문은 출발 앵커가 없다 — "전체에서 무엇이 반복되나" 는 그래프 전역을 조감해야 한다. GraphRAG 같은 도구는 이 공백을 **커뮤니티별 요약을 사전 생성** 해 메운다. 전역 질문이 오면 그 요약들을 이어 답한다.

그런데 이 방식은 Arche 의 정체성과 충돌한다. ADR-0016 은 측정을 근거로 **답변 생성 LLM 을 Arche 밖에 두기로** 확정했다 — Arche 는 구조화된 사실만 내놓고, 답변 문장은 바깥 에이전트가 쓴다. 커뮤니티 요약은 사전 생성된 LLM 출력이다. 이걸 Arche 안에 두면 정체성이 뒤집힌다.

### 절충 후보 — 탐지와 요약을 가른다

전역 공백을 좁히되 정체성을 지키는 길은 **커뮤니티 탐지와 요약을 갈라서** 탐지만 노출하는 것이다.

- **탐지** — "이 12개 노드가 한 군집이다" 라는 구조 정보. 답변이 아니라 사실이다.
- **요약** — 그 군집을 문장으로 푸는 것. 이건 답변이라 에이전트(바깥 LLM)가 회수한 서브그래프로 직접 만든다.

이렇게 가르면 Arche 는 여전히 사실만 주고, 전역 질문의 재료(어떤 노드가 한 덩어리인지)는 제공한다. 원칙을 지키면서 공백을 좁힌다.

### 왜 지금 결정이 필요했나

이건 범위와 제품 정체성이 걸린 결정이라 코드보다 먼저 방향을 확정해야 한다(HITL, 사람 판단). 지원 여부를 열어두면 이후 프리미티브 설계와 저장 전략이 흔들린다. 시장 조사 세션(2026-07-12)에서 GraphRAG 의 전역 검색 접근을 확인한 것이 이 결정을 촉발했다.

## Decision — 무엇을 결정했나

### D1. 전역/주제 질문은 MVP 에서 지원하지 않는다

커뮤니티 탐지 프리미티브(get_communities 류)를 **MVP 표면에 지금 노출하지 않는다**. 이유는 둘이다.

- ADR-0001 의 MVP 가설은 자연어 도메인 **단발 지역 Q&A** 의 Pareto 우월 하나만 검증한다. 전역 질문은 그 가설 밖이다.
- 탐지 프리미티브를 지금 더하면 ADR-0006 표면이 넓어지고, 커뮤니티 재빌드 비용(D4)까지 MVP 로 끌려 들어온다.

### D2. 지원하게 될 때의 형태 — 커뮤니티 탐지-only

전역 질문을 나중에 지원한다면, 그 형태는 **탐지만 노출** 로 확정한다. 프리미티브는 "어떤 노드가 한 군집인가" 의 구조 정보만 반환한다. 요약은 에이전트가 그 군집의 서브그래프를 회수해 직접 만든다. Arche 는 답변 문장을 생산하지 않는다 — ADR-0016 원칙 유지.

### D3. 커뮤니티 요약 사전 생성은 영구 제외

GraphRAG 식으로 **커뮤니티별 요약을 사전 생성해 노출** 하는 형태(위 절충 후보의 반대편)는 선택지에서 영구히 제외한다. 사전 생성 요약은 답변 LLM 출력이라 ADR-0016 을 정면으로 위반한다. 추가로 요약은 그래프가 바뀔 때마다 낡고, Arche 의 해석이 답변에 새어 들고, Arche 가 무거워진다. 이건 "나중에 재검토" 대상이 아니라 방향에서 배제한다.

### D4. 재빌드 비용과 idempotent 적재의 상호작용

탐지-only 여도 커뮤니티는 **그래프가 바뀔 때 재계산** 이 필요하다 — 노드/관계가 늘면 군집 경계가 달라진다. 이건 idempotent 증분 적재(ADR-0001 D6: 같은 소스 = 같은 그래프)와 상호작용한다. 다음 두 질문은 **지원이 확정되는 시점의 후속 ADR** 에서 정한다.

- 탐지 결과를 **저장(캐시)** 할지, 요청 시 **즉석 계산** 할지.
- 증분 적재가 캐시된 커뮤니티를 어떻게 무효화/재계산하며 결정성을 유지하는지.

MVP 는 탐지를 노출하지 않으므로 이 비용을 지금 지지 않는다.

### D5. 지원으로 뒤집힐 때의 후속 분할

전역 질문 지원으로 결정이 뒤집히면(post-MVP), 다음을 별도 구현 이슈로 쪼갠다.

- 탐지 알고리즘 선택(Leiden vs 대안)과 파라미터.
- get_communities 프리미티브 계약(입출력, 페이지네이션, ADR-0006 정합성).
- 저장 전략(캐시 vs 즉석 계산)과 증분 적재 무효화(D4).

## Considered Options

### 옵션 1 — MVP 에 탐지 프리미티브를 지금 추가

거부. 전역 질문은 MVP 가설(단발 지역 Q&A) 밖이라 검증에 기여하지 않는데, 표면(ADR-0006)을 넓히고 커뮤니티 재빌드 비용 설계를 MVP 로 끌어들인다.

만약 이걸 택했다면, MVP 종료 보고서 한 장(ADR-0001 D7)이 "전역 질문 지원이 지역 Q&A 정확도에 준 영향" 이라는 변수를 하나 더 풀어 해석해야 했고, 재빌드/증분 적재 상호작용을 가설 검증 전에 고정하는 비용을 치렀을 것이다.

### 옵션 2 — 커뮤니티 요약까지 노출 (GraphRAG 방식)

거부. 사전 생성 요약은 답변 LLM 출력이라 ADR-0016(답변 외부화)을 정면으로 위반한다. Arche 를 사실상 GraphRAG 로 만들어 제품 정체성을 판다.

만약 이걸 택했다면, 그래프가 바뀔 때마다 요약을 다시 써야 하는 낡음 문제를 떠안고, Arche 의 해석이 답변에 섞여 "구조화된 사실만 준다" 는 계약이 무너졌을 것이다.

### 옵션 3 — 완전 미지원, 방향도 남기지 않음

거부에 근접했으나 미채택. 지원을 안 하는 건 맞지만 방향까지 비워두면, 나중에 이 문제를 다시 열 때 "탐지냐 요약이냐" 를 원점부터 재고민해야 한다. GraphRAG 식 요약이 다시 후보로 올라올 위험도 남는다.

### 옵션 4 — MVP 미지원 + 탐지-only 방향 확정 (채택)

채택. 지금은 표면을 넓히지 않고(옵션 1 회피), 정체성을 지키며(옵션 2 회피), 나중의 방향은 못박아 재고민을 없앤다(옵션 3 회피). 지원이 확정될 때 탐지-only 형태에서 곧바로 구현 분할로 넘어간다.

## Consequences

### 즉시 영향

- 이 ADR 자체는 **코드를 바꾸지 않는다** — 결정(경계와 방향)을 기록하는 결정 이슈다.
- MVP 표면(ADR-0006)은 그대로다 — 커뮤니티 프리미티브는 추가되지 않는다.
- ADR-0016 의 답변 외부화 원칙이 전역 질문 영역까지 명시적으로 확장된다.

### 코드 작업 시 기억할 점

- 커뮤니티 탐지/요약을 프리미티브 계층에 임시로 끼워 넣지 않는다 — MVP 미지원(D1)이다.
- 전역 질문을 답변 문장으로 되돌려 주는 어떤 경로도 Arche 안에 두지 않는다 — 요약은 에이전트 몫(D2, D3).
- 지원이 확정되면 탐지-only 로 시작한다 — 요약 사전 생성은 배제된 선택지다(D3).

### post-MVP 재검토 트리거

- 실측/사용에서 전역 질문 공백이 도메인 활용의 병목으로 확인될 시.
- 코드베이스 적재(post-MVP 1순위) 등에서 "모듈/서브시스템 전체 주제" 같은 전역 질문 수요가 성숙할 시.
