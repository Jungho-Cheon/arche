# ADR-0017: 허브 인지 경로 점수 — promiscuous 허브 down-weighting + RELATES_TO 경로 제한

Status: accepted
Date: 2026-06-23
Phase: 측정 기반 정밀도 개선 (ADR-0016 후속, MedHop 30% 천장 진단)
Amends: [ADR-0016](./0016-agentic-graphonly-and-quantitative-extraction.md) D4 (다음 레버를 "병합 강화" 에서 "경로 정밀도" 로 교정)

## 용어 한 줄 풀이 (처음 등장)

- **프리미티브 (primitive)**: 그래프에 대한 기본 읽기 동작. 여기서는 두 엔티티
  사이 경로를 찾는 `find_path` 가 핵심.
- **promiscuous 허브 (promiscuous hub)**: 수많은 다른 엔티티와 연결된 노드. 예:
  여러 약물이 공통으로 결합하는 단백질, 또는 추출 과정에서 과하게 뭉쳐진 개념
  노드. "다 같이 연결돼 있어서" 두 엔티티를 잇지만 그 연결이 *특정한 의미* 를
  담지 않는다.
- **degree**: 한 노드에 붙은 관계(엣지)의 수. degree 가 클수록 허브에 가깝다.
- **hub_score**: 한 경로의 *중간* 노드들(양 끝점 제외) degree 를 log(1+degree)
  로 누적한 값. 0 에 가까울수록 *구체적인* (믿을 만한) 경로, 클수록 허브를 다리로
  쓴 *모호한* 경로.
- **끝점 (endpoint)**: 경로의 양 끝 노드 = 질문이 묻는 두 엔티티 그 자체.
- **de-masking (탈마스킹)**: 평가용으로 식별자가 가려진(masked) 코퍼스에서, 추출
  LLM 이 자기 사전 지식으로 가려진 ID 를 실제 이름으로 되돌려 버리는 현상.
- **RELATES_TO / EMITTED_IN**: 그래프의 두 관계 종류. RELATES_TO 는 *엔티티 간
  의미 관계*, EMITTED_IN 은 *엔티티가 어느 적재 작업에서 나왔는가* 라는 출처 기록.

## TL;DR

ADR-0016 은 관계-사슬 도메인(MedHop biomedical)의 30% 천장 원인을 "문서 간 엔티티
병합 부족"으로 지목했다. 라이브 그래프 실측으로 이 진단을 **부분적으로 뒤집는다**.

1. **천장의 다수는 재현율(병합)이 아니라 정밀도 문제였다.** 오답 10 문항 중 5 개는
   경로가 *있는데도* 틀렸다 — promiscuous 허브를 다리로 쓴 *가짜 경로* 가 엉뚱한
   후보로 이끌었다. 3 개만이 경로 부재(재현율). 그러므로 "더 병합" 은 오히려
   허브를 키워 정밀도를 *악화* 시킨다.
2. **수정**: `find_path` 가 같은 길이의 경로 중 **중간 노드 degree 가 낮은(구체적)
   경로를 우선** 하도록 정렬하고, `hub_score` 를 응답에 노출해 소비 에이전트가 허브
   경로를 의심하게 한다. **끝점은 점수에서 제외** — 금융처럼 정답이 고-degree
   끝점인 도메인을 회귀로부터 보호.
3. **부수 수정**: 경로 탐색을 `RELATES_TO` 관계로 제한. 무제한 탐색이 `EMITTED_IN`
   을 타고 출처 노드(`IngestionRun`)를 경유하며 (a) 직렬화 크래시, (b) "같은 적재
   작업에서 나왔다" 는 무의미한 가짜 다리를 만들던 회귀를 동시에 제거.
4. **정직한 한계**: MedHop *절대 정답률* 재측정은 별개 교란으로 막힌다 — 추출 LLM
   이 321 개 DrugBank ID 중 250 개를 탈마스킹해, 정답 후보가 마스킹 ID 로는 그래프
   에서 찾히지 않는다. 이는 MedHop 마스킹 설계 고유의 artifact 로 실제 코퍼스엔
   없다. 본 ADR 의 수정은 메커니즘과 금융 무회귀로 검증하고, MedHop 절대값 개선은
   탈마스킹 방지(후속)와 묶어 다룬다.

## 이 ADR 을 읽는 이유

- ADR-0016 의 "다음 레버 = 병합 강화" 를 *그대로 실행하면 정밀도가 나빠진다* . 그
  교정의 근거.
- `find_path` 응답에 새로 생긴 `hub_score` 필드의 의미와, 소비 에이전트가 이를
  어떻게 써야 하는지.
- 금융 도메인(97%)을 깨지 않으면서 관계 도메인 정밀도를 올리는 설계 원칙(끝점 제외).

## Context — 측정 사실 (라이브 그래프 실측, 2026-06-23)

대상: ADR-0016 의 MedHop graph-only run(289 PubMed abstract, 3,508 엔티티). 그래프는
실측 시점까지 neo4j 에 그대로 남아 있어 *재적재 없이* 직접 질의했다.

### 30% 의 분해 — 재현율이 아니라 정밀도

오답을 "경로 존재 여부"로 가르니(에이전트 자신의 run 로그 + 그래프 직접 질의):

| 구분 | 개수 | 의미 |
|---|---|---|
| 경로 있음 & 정답 | 2 | 그래프가 끝까지 작동 |
| 경로 없음 & 정답 | 1 | 외부지식 추측 적중 (순수 그래프 정답은 2/10) |
| **경로 있음 & 오답** | **5** | **경로는 있는데 허브 다리로 엉뚱한 후보 선택 (정밀도)** |
| 경로 없음 & 오답 | 2 | 사슬 자체가 그래프에 없음 (재현율) |

가장 큰 실패 묶음은 정밀도(5)다. 다섯 오답의 경로는 모두 promiscuous 허브를 경유한다
(공유 단백질 P00374 degree 64, 세로토닌 수용체, eNOS 등). 에이전트의 판단 규칙이
"이 허브를 통해 닿는 후보"인데, 허브가 너무 많은 후보와 연결돼 *닿지만 틀린* 후보를
고른다.

### 허브 집중도 (정량 근거)

degree 분포는 median 1, 평균 2.88, p95 = 9, **최대 339**. 상위 10 개 노드(전체
3,508 의 0.28%)가 전체 엣지 끝점의 **8.4%** 를 차지한다. 1 위 "Contact sensitization
to oxazolone"(degree 339)는 실험 조건을 뭉뚱그린 추출 artifact 로, 혼자 전체 끝점의
3.7% 를 가진다.

대표 사례(MH_dev_4): 정답이 아닌 후보로의 *유일한* 경로가
`DB00977 → [Contact sensitization to oxazolone, deg 339] → P62324 → P27708 → DB03459`.
수정 후 `find_path` 가 이 경로에 **hub_score = 9.23** 을 부여 — "이 연결은 허브
다리이니 근거로 삼기 전에 의심하라"는 정량 신호다. 반면 구체적 1-hop 상호작용은
hub_score = 0.0.

### 별개 교란의 발견 — 탈마스킹

질문이 참조하는 321 개 DrugBank ID 중 **71 개만** 그래프에 ID 노드로 존재하고
**250 개는 부재** 다. 추출 LLM(gpt-4.1)이 대부분의 ID 를 실제 약물명으로 되돌렸기
때문이다(예: DB08815 → lurasidone). MedHop 의 정답 후보(DB00605/DB00619/DB00677 등)가
바로 이 부재 집합에 있어, 마스킹 ID 로는 그래프에서 닿지 않는다. 이는 MedHop 의
마스킹 설계가 LLM 추출과 충돌해 생긴 artifact 이며, 실명을 일관되게 쓰는 실제 코퍼스
에서는 발생하지 않는다. 따라서 본 수정의 효과를 MedHop *절대 정답률* 로 환산하는 것은
이 교란에 가려 부정확하다.

## Decision

### D1. find_path — 허브 인지 정렬 + hub_score 노출 (끝점 제외)

`allShortestPaths` 가 돌려주는 같은 길이 경로들을, 각 경로의 *중간* 노드(끝점 제외)
degree 를 `log(1+degree)` 로 누적한 `hub_score` 오름차순으로 정렬해 가장 구체적인
경로부터 `max_paths` 만큼 돌려준다. `hub_score` 는 응답 `PathSegment.hub_score` 로
노출한다.

WHY 끝점 제외: 금융 도메인에서 정답은 흔히 회사나 핵심 metric 같은 *고-degree 끝점*
이다(American Express degree 841). 끝점에 페널티를 매기면 모든 금융 경로가 깎인다.
중간 노드만 합산하면 "허브를 *경유* 하는" 가짜 다리만 골라 페널티를 준다.

WHY 경로를 버리지 않고 *정렬+신호* 만: 허브 경로도 때로 유일한 단서다. 떨어뜨리면
재현율을 해친다. 대신 낮은 우선순위 + 높은 hub_score 로 표시해 *판단은 에이전트에게*
남긴다.

### D2. 경로 탐색을 RELATES_TO 로 제한

`allShortestPaths((a)-[*1..N]-(b))` 의 무제한 관계 패턴을
`allShortestPaths((a)-[:RELATES_TO*1..N]-(b))` 로 바꾼다. 무제한 패턴은 출처 관계
`EMITTED_IN` 을 타고 `IngestionRun` 노드(이름 속성 없음)를 경유해 (1) 직렬화 시
`KeyError: 'name'` 크래시, (2) "같은 적재 작업 산출물" 이라는 의미 없는 다리로 두
엔티티를 잇는 가짜 경로를 만들었다. 의미 그래프 경로는 엔티티 간 관계만 따라야 한다.

### D3. ADR-0016 D4 교정 — 다음 레버는 "병합 강화" 가 아니라 "경로 정밀도"

ADR-0016 은 다음 ingest 레버를 "문서 간 엔티티 병합 강화" 로 적었다. 측정은 그 반대
를 가리킨다: 천장의 다수(5/10)는 *경로가 있는데 틀린* 정밀도 문제이고, 무차별 병합은
허브를 키워 정밀도를 악화시킨다. 따라서 우선순위를 재정렬한다.

1. (가장 큼) 경로 정밀도 — 본 ADR 의 허브 인지 점수 + (후속) 타입된 관계 추출.
2. (작음) 재현율 — 누락된 *특정* 연결 노드의 병합. 무차별 병합이 아니라 *선별* 병합.

> **추가 실측 교정 (2026-06-23)**: 위 "정밀도(5/10)" 는 에이전트의 chain 로그에서
> "경로를 찾았다" 고 보고한 문항 수다. 그러나 10 문항 전체를 그래프에서 직접 확인하니
> **오답 7 개 *전부* gold 후보가 그래프에 부재** (탈마스킹으로 마스킹 ID 노드가 없음).
> 즉 그 "정밀도" 실패들은 *구조적으로는 재현율* — 에이전트가 gold 가 없어 *닿는 다른*
> (허브 다리) 후보를 자신 있게 골랐다. 따라서 **MedHop 에서 hub_score 는 정답률을 못
> 올린다** (gold 가 아예 없어 flip 할 대상이 없음). hub_score 의 MedHop 가치는 정확도가
> 아니라 *calibration* — 허브 다리 후보를 "근거 약함" 으로 표시해 *자신 있는 오답* 을
> 줄이는 것(MH_dev_4 의 오답 경로 hub_score 9.23 → 불신 대상). 정확도 개선은 탈마스킹
> artifact 가 없는 도메인(금융과 실 코퍼스)에서 gold 가 닿을 때 발생한다. MedHop 의 진짜
> 레버는 재현율(탈마스킹 방지), hub_score 는 그와 *직교* 하는 일반 개선.

## 검증 (측정 인용)

- 단위 테스트: `apps/api` 224 passed (서명 변경 무회귀).
- 통합 테스트(실 neo4j 5.15, testcontainers): `test_neo4j_primitives_regression.py`
  6 passed — 신규 `test_find_shortest_paths_prefers_specific_over_hub`(같은 길이 두
  경로 중 구체적 경로가 hub_score 낮게 먼저), `test_find_shortest_paths_direct_edge_zero_hub_score`
  (1-hop 직접 경로 hub_score 0.0) 포함. 전체 선택 스위트 234 passed.
- **금융 무회귀 스모크(실 FinanceBench 그래프, 5,654 노드)**:
  - 끝점 = American Express(degree 841)인 경로 → hub_score 0.0 (끝점 제외 확인).
  - 회사 허브를 *경유* 하는 metric→metric 경로 → 누락 없이 반환, hub_score 6.736
    (= log(1+841)) 로 정직하게 표시. 경로를 버리지 않음.
- 메커니즘 실증(실 MedHop 그래프): baseline 의 오답 경로(DB00977→DB03459)가 deg-339
  artifact 다리로만 닿으며 이제 hub_score 9.23 으로 표시됨.
- **hub_score 분리력 측정(MedHop 10 문항, gold 대비 pick 경로 hub_score)**: 오답 7 개
  *모두* gold 미도달(탈마스킹) → hub_score 가 wrong→gold 로 flip 시킬 수 있는 문항
  **0 개**. MedHop 에서 hub_score 의 정확도 기여는 0 이며(재현율 천장), 효과는
  calibration(자신 있는 오답 표시)에 국한됨을 정량 확인. 이 측정이 D3 의 "정밀도
  레버" 주장을 *MedHop 한정으로는* 반증 — 정확도 레버는 비-마스킹 도메인 몫.
- **금융 crosscompany 정확도 측정(비-마스킹, gold 도달 가능, 5 문항 anchor→회사
  find_path)**: hub-aware 4/5 = length-only 4/5. **금융에서도 hub_score 정확도 기여
  0**. 이유: 판별 개념이 정답 회사에 *직접*(length-1, hub_score 0) 연결돼 깎을 허브
  다리가 없음. 유일 오답(X08)은 허브가 아니라 anchor 어휘 모호성. **결론(정직)**:
  hub_score 의 정확도 가치는 가용 두 벤치마크에서 *입증되지 않았다* — 각각 다른
  이유(MedHop=재현율 천장, 금융=직접 연결). hub_score 가 정확도를 올리는 조건은
  *gold 가 2-hop 이상이고 그 정답 경로가 더 짧거나 같은 허브 다리와 경쟁하는* 좁은
  영역이며, 두 벤치마크 모두 이 영역을 자극하지 않는다. hub_score 의 *검증된* 가치는
  (1) 무회귀(끝점 제외), (2) RELATES_TO 버그픽스, (3) calibration 신호이지 *정확도
  향상이 아니다*.

## 재적재 검증 (2026-06-23 — 예방 가드 end-to-end 측정)

stoplist+패턴(over-merge 예방)과 식별자-별칭 프롬프트를 넣은 *새 코드로* MedHop 289
abstract 를 신선한 neo4j 에 전량 재적재(약 2.5 시간)하고 베이스라인과 비교.

| 지표 | 베이스라인(옛) | 새 그래프 | 판정 |
|---|---|---|---|
| 최대 degree | 339 (가짜 허브) | **71** | 4.8배 ↓ |
| 최대 별칭 수 | 95 | **13** | 불량 허브 소멸 |
| 담론 표현이 매칭 색인에 | 다수 | **0** | stoplist 작동 |
| 엔티티 / 관계 | 3508 / 4577 | 3141 / 4150 | 군더더기 ↓ |
| broken gold 도달 가능 | 0/7 | **2/7** | 식별자-별칭 효과 |

- **예방 가드: 결정적 성공.** deg-339 불량 허브(여러 문서의 무관 엔티티가 "this study"
  등으로 뭉친 노드)가 완전히 사라졌다. 도메인 무관 일반 개선.
- **재현율: 부분.** 식별자-별칭으로 끊긴 사슬 2/7 재연결(시뮬 예측과 일치). 단 **3/7
  은 gold 가 그래프에 *노드조차 없음*** — 그 약물의 상호작용을 추출이 *처음부터 누락*.
  별칭/병합으로는 못 고침.
- **정확도: 미확정.** 싼 결정적 후보 랭킹(베이스라인 2/10 vs 새 1/10)은 노이즈이고
  신뢰 불가(최단경로 선택이 추론을 못 해 실정답도 놓침). 공정한 수치는 에이전트
  재실행 필요 — 비용 대비 가치 낮아 보류(전략 결론 불변).
- **드러난 진짜 레버**: gold 3/7 이 "경로 없음" 이 아니라 "노드 없음" → 남은 병목은
  엔티티 해소가 아니라 **관계 추출 완전성**(문서에 있는 상호작용을 더 빠짐없이 추출).

## Consequences

### 즉시 영향

- `find_path` 응답에 `hub_score: float` 필드 추가(가법적, 하위 호환). MCP `find_path`
  도 `model_dump` 로 자동 포함.
- `find_path` 가 출처(EMITTED_IN) 경로를 더 이상 돌려주지 않음 — 의미 경로만. 이는
  버그 수정이며 의도된 동작 변화.
- 금융 도메인 무회귀(끝점 제외 + 경로 보존).

### 코드 작업 시 기억할 점

- 경로 점수의 끝점 제외 불변식: `node_objs[1:-1]` 만 합산. 끝점을 합산에 넣으면 금융
  회귀가 즉시 재발한다.
- 소비 에이전트(eval 컬럼과 외부 클라이언트)는 `hub_score` 가 높은 경로를 *근거 채택
  전에 의심* 하도록 프롬프트해야 실효가 난다. 노출만으로는 부족.

> **교정 (2026-06-23, 별칭 인지 재측정)**: 아래 후속 2 의 "탈마스킹 → gold 부재"
> 진단은 *틀렸다*. 노드 해석을 name 만이 아니라 **aliases 까지** 포함해 다시 보면,
> 오답 7 개의 gold 중 4 개(DB01151, DB00605=sulindac, DB00281=lidocaine, DB00559)는
> 그래프에 *엔티티로 존재* 한다(코퍼스가 부분 마스킹이라 같은 abstract 에 ID 와 실명이
> 함께 등장 → 추출이 실명을 name, 마스킹 ID 를 alias 로 올바로 묶었다). 전체 ID 커버리지
> 도 name-only 71 → name+alias **127**. **진짜 실패는 "gold 엔티티 부재" 가 아니라
> "subject→gold 사슬 단절"**: gold 가 존재해도 subject 에서 4-hop 안에 경로가 없다.
> 원인은 (1) gold 약물의 관계 *과소추출*(예: sulindac 이웃 1 개), (2) 중간 단백질의
> 표기 *파편화*(예: "thymidylate synthase" / "thymidylates synthase (P04818)" / "P00374"
> 가 별개 노드로 흩어져 공유 다리가 끊김). 이는 **관계 recall + 엔티티 동일성 해소**
> 문제 — 즉 [ADR-0016](./0016-agentic-graphonly-and-quantitative-extraction.md) D4 의
> *원래* 방향(문서 간 병합)이 옳았고, 본 ADR D3 의 "정밀도가 레버" 교정은 *MedHop 에
> 한해 과도* 했다. hub_score 정확도 기여 0 (별칭 인지 재측정에서도 flip 0)은 그대로
> 유효하나, 그 이유는 "gold 부재" 가 아니라 "사슬 단절(recall)" 이다.

### 발견한 개선 방향 (우선순위, 재적재 측정 반영)

1. **관계 추출 완전성 (MedHop 의 진짜 1순위 레버)** — 재적재로 확정: gold 3/7 이
   "경로 없음" 이 아니라 *노드조차 없음* = 그 약물의 상호작용을 추출이 처음부터 누락.
   엔티티 해소(별칭/병합)는 2/7 만 열었고 천장이 여기. 한 엔티티의 상호작용을 더
   빠짐없이 뽑는 추출(다단계/관계-집중 프롬프트 또는 재추출 패스)이 다음 레버.
2. **name↔근접ID 후처리 바인딩** — ✅ **구현됨 (2026-06-24)**. 식별자-별칭 프롬프트
   (원칙 4(a))는 약물(lurasidone↔DB08815)엔 성공하나 "serotonin P34969" 류 *이름 옆
   bare ID*, "thymidylate synthase (P04818)" 의 괄호 ID 를 별도 노드로 남겼다. 적재
   시 `extract_identifier_aliases(name)`(identity.py)로 이름에서 *구조적 식별자* 를
   결정적으로 뽑아 alias 로 보강 → 그 ID 로 검색과 병합이 가능. **고정밀 게이트**(글자 +
   숫자 3개 이상)로 generic 코드(10-K/8-K/B12 등)를 배제해 over-merge 를 막는다.
   `_upsert_entities` 루프 최상단에서 적용(매칭 Step 2 + 저장 alias 둘 다 반영).
   end-to-end recall 효과는 재적재 측정 필요(시뮬레이션 예측 +2/7). 단위 6 테스트.
3. **이웃/서브그래프 허브 인지 절단** — ✅ **구현됨 (2026-06-24)**.
   `expand_neighbors`/`expand_subgraph` 의 BFS 가 max_nodes 에서 잘릴 때, 이웃을
   `other_degree`(연결 수) 오름차순으로 처리해 *낮은 degree(구체적) 이웃을 먼저 채우고
   promiscuous 허브를 먼저 버린다*. find_path 의 hub_score 와 같은 원리를 에이전트
   주력 도구로 확장(끝점/진입점은 절단 대상이 아니라 면제). 절단이 없을 땐 순서만 바뀌고
   *누락은 없다*. 효과는 *조밀/대형 그래프에서 큼*(MedHop 처럼 작은 그래프에선 절단이
   드물게 발동). `_order_rows_by_degree` + 확장 cypher 에 degree 서브쿼리.
4. **추출 버전을 short-circuit 게이트에 포함 (코드-델타)** — ✅ **구현됨
   (2026-06-23)**. 옛 short-circuit 은 *파일 내용* 해시라 프롬프트/추출 로직을 바꿔도
   "변경 없음" 으로 옛 추출을 유지했다(그래서 이번 검증엔 신선 그래프 full 재적재가
   필요했다). 이제 `IngestionRun.extractor_version = f"p{INGEST_PIPELINE_VERSION}:{llm.
   extraction_fingerprint()}"` 를 저장하고, short-circuit 을 `(path, hash,
   extractor_version)` 3 자 일치로 강화했다. `extraction_fingerprint()` 는
   SYSTEM_PROMPT + 추출 스키마 + model_id 의 sha256(자동), `INGEST_PIPELINE_VERSION` 은
   매칭/정규화/stoplist 등 프롬프트 밖 로직 변경 시 수동 +1. 프롬프트 한 줄만 바꿔도
   같은 파일이 재추출되고, 안 바뀐 파일은 여전히 skip → 코드 변경을 델타로 잡는다.
5. **eval 에이전트가 hub_score 소비** — ✅ **구현됨 (2026-06-24)**. `serialize_subgraph`
   가 각 경로에 `[hub_score=X.XX]` 를 노출하고 임계(≥2.0) 초과 시 `⚠허브경유-근거약함`
   마커를 단다. `ARCHE_ANSWER_SYSTEM` 프롬프트에 "두 보기가 경쟁하면 hub_score
   낮은 경로 우선, ⚠ 경로로만 닿는 보기는 강한 근거로 삼지 않는다" 규칙 추가. 답변
   LLM 이 가짜 허브 다리를 근거 채택 전에 의심하게 된다. end-to-end 재측정(MedHop 과
   FinanceBench)은 비용 때문에 별도. eval serializer 단위 테스트 추가.
6. **이미 망가진 그래프의 탐지 (정적 3단의 3번)** — ✅ **탐지 구현됨 (2026-06-24)**.
   예방(stoplist)이 *앞으로의* 적재는 막으나 옛 그래프엔 불량 노드가 남는다.
   `detect_overmerged_entities`(identity.py) — 결정적 3 신호로 플래그: (1) 별칭 수
   이상치(>30), (2) 서로 다른 구조적 식별자 다수(>2 = 별개 엔티티 병합 흔적), (3)
   deixis/stoplist 별칭이 매칭 색인에 새어든 흔적. `Neo4jGraphRepository.find_overmerged_entities()`
   로 라이브 그래프에 적용. **실 baseline 검증**: 수동으로 찾았던 deg-339 불량 노드를
   세 신호 모두로 독립 재발견(+ 33 개). 교정(분리/정리)은 출처 기준 deterministic
   분리로 후속(운영자 검토 필요, 위험 관리).

## 정직한 한계 (과대주장 방지)

1. **MedHop 절대 정답률 개선은 본 ADR 로 입증하지 않았다.** (정정) 원인은 "탈마스킹
   으로 gold 부재" 가 아니라 **subject→gold 사슬 단절(recall)** 이다(위 "교정" 박스).
   gold 가 닿지 않으니 hub_score(정밀도)는 flip 시킬 대상이 없어 MedHop 정확도 기여 0.
   본 ADR 은 메커니즘(가짜 다리 식별)과 금융 무회귀까지를 검증 범위로 하고, MedHop
   정확도 레버는 recall(후속 2)로 분리한다.
2. **find_path 단독 변경.** 에이전트의 주력 도구인 이웃/서브그래프 확장은 아직
   허브 인지가 아니다(후속 1).
3. **n=10.** 정밀도/재현율 분해의 표본이 작다 — 방향성 신호.
