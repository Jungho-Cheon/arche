# ADR-0020: 투 트랙 저장소 — 임베디드 기본값(Kuzu) + Neo4j 프로덕션

Status: proposed
Date: 2026-07-13

## TL;DR

ADR-0004 는 별도 벡터 DB 없이 그래프 DB 내장 인덱스를 쓰기로 정했고, 이 결정이 사실상 **Neo4j 서버를 필수 의존성**으로 만들었다. Arche 를 쓰려면 먼저 Neo4j 컨테이너를 띄워야 한다. 그런데 제품 정체성인 "AI 에이전트가 MCP 로 붙는 세컨드브레인" 과 그 문서 서사("에이전트에 5줄로 붙이기", ADR-0006/#145)는 "먼저 Neo4j 컨테이너부터 띄우세요" 와 정면으로 부딪힌다.

**이중 트랙을 채택한다.** 체험과 단일 사용자 환경은 서버 없이 `pip install` 만으로 도는 **임베디드 백엔드**로, 동시성/여러 사용자 간 namespace 공유/규모가 필요한 프로덕션은 **Neo4j** 로 간다. 능력별 포트(ADR-0018 — GraphStore / VectorIndex / LexicalIndex)가 이미 이음매를 분리해 뒀으므로, 이건 구조 변경이 아니라 어댑터 추가다.

임베디드 기본 백엔드는 **Kuzu** 로 정한다. 후보 중 유일하게 진짜 in-process 이면서 그래프 순회 + 벡터 검색 + 풀텍스트를 한 컴포넌트로 충족한다. upstream 이 2025-10 에 아카이브된 리스크는 안정 릴리스 0.11.3 고정과 유지보수 포크 경로로 완화한다.

> **임베디드(in-process) DB** — SQLite / DuckDB 처럼 별도 서버 프로세스 없이 애플리케이션 프로세스 안에서 라이브러리로 도는 데이터베이스. 파일 하나가 곧 DB 이고, 접속할 네트워크 주소가 없다.
>
> **HNSW** — Hierarchical Navigable Small World. 벡터 근사 최근접 탐색(ANN)에 널리 쓰는 인덱스 구조. 대량 임베딩에서 "의미가 가까운" 벡터를 빠르게 찾는다.
>
> **GQL (ISO/IEC 39075:2024)** — 2024-04 에 나온 그래프 질의 언어 국제 표준. 관계형의 SQL 에 대응하는 그래프용 표준이다. 아직 벤더별 구현/수렴이 초기라 방언 차이를 완전히 없애지는 못한다.

## 이 ADR 을 읽는 이유

- Arche 를 왜 *Neo4j 없이도* 띄울 수 있게 하려는지, 그 경계가 어디인지 알고 싶다면
- 임베디드 백엔드로 왜 하필 Kuzu 를 골랐고, 아카이브된 프로젝트를 택한 근거가 궁금하다면
- 임베디드와 Neo4j 사이 전환을 어떻게 하는지, "설정만 바꾸면 교체" 가 어디까지 사실인지 확인하려면

## 읽기 전 권장 배경

- [ADR-0004 — 벡터 인프라 결정](./0004-vector-infra-graph-db-internal-index.md) — 본 ADR 이 amend 하는 결정. "별도 벡터 DB 없이 그래프 DB 내장 인덱스" 원칙은 그대로 두고, 그 위에 임베디드 트랙을 더한다.
- [ADR-0018 — monorepo 구조 + agnostic 경계](./0018-monorepo-and-agnostic-boundaries.md) — 능력별 포트(GraphStore / VectorIndex / LexicalIndex). 이 분리가 이중 트랙을 어댑터 추가만으로 가능하게 하는 전제다.
- [ADR-0015 — 공유 KB 운영 모델](./0015-shared-kb-operating-model.md) — 여러 주체가 namespace 로 나눠 같은 그래프를 동시에 쓰는 시나리오. 임베디드가 못 받는 구간이자 Neo4j 를 프로덕션 쪽에 남기는 이유.

## Context — 왜 이 결정이 필요했나

### ADR-0004 가 남긴 긴장

ADR-0004 는 "벡터 검색이 필요하다고 별도 벡터 DB 가 필요한 건 아니다" 를 논증하며, dense 임베딩을 그래프 DB 내장 인덱스에 저장하기로 했다. 이 결정의 제약은 *벡터 인덱스 + 풀텍스트 인덱스 + 그래프 순회 셋을 한 컴포넌트에서 제공* 해야 한다는 것이었고, 그 조건을 가장 잘 만족하는 벤더로 Neo4j 5.15+ 를 골랐다. 결과적으로 Arche 를 돌리려면 Neo4j 서버가 떠 있어야 한다.

이건 검증 단계에서는 합리적이었다. 문제는 제품 정체성이 굳으면서 드러났다.

### 시장 조사가 드러낸 트레이드오프 (2026-07-12)

- **LightRAG / HippoRAG / GraphRAG** 는 임베디드/파일 기반(NetworkX / igraph / Parquet)이라 서버 없이 `pip install` 만으로 돈다. 채택 문턱이 낮다. 대신 세 인덱스(그래프 + 벡터 ANN + 풀텍스트)를 통합하고 진짜 그래프 순회를 얻으려면 손으로 얽어야 한다.
- **Graphiti / Cognee** 는 서버형(Neo4j)과 임베디드(Kuzu / FalkorDB)를 **둘 다** 제공하는 이중 트랙으로 "체험은 임베디드, 확장은 서버" 를 잡는다.

Arche 의 MVP 모양 — 단일 환경, 본인 운영, 읽기 위주 — 은 임베디드가 유리한 조건이다. 그리고 방금 확정한 문서 서사(#145 "에이전트에 5줄로 붙이기")는 무서버 온보딩을 기술 전제로 깔고 있다. "5줄로 붙인다" 면서 그 앞에 "Neo4j 컨테이너부터 띄우세요" 가 붙으면 채택 곡선의 맨 앞에서 사람을 잃는다.

### 왜 지금 사람 판단(HITL)이 필요했나

이건 인프라 방향 결정이다. 임베디드를 얹으면 얻는 것(체험 문턱 인하)과 지는 것(어댑터 이중화, 동시성 상한, 특정 엔진 의존)이 모두 실재하고, 어느 쪽을 감수할지는 코드에서 읽어낼 수 없는 판단이라 사람이 정해야 했다. 조사 과정에서 이슈가 예로 든 "Kuzu" 의 전제도 흔들렸다(아래 D2).

## Decision — 무엇을 결정했나

### D1. 이중 트랙을 채택한다

저장소 백엔드를 두 갈래로 제공한다. 경계는 *부하의 성격* 으로 가른다.

| | 임베디드 트랙 (기본값) | Neo4j 트랙 (프로덕션) |
|---|---|---|
| 대상 | 체험, 단일 사용자, 읽기 위주, dogfooding | 동시 쓰기, 여러 주체의 namespace 공유, 규모 |
| 실행 | 서버 없이 `pip install` → 파일 DB | Neo4j 컨테이너/서버 |
| 강점 | 채택 문턱, 온보딩 서사 완성 | 동시성, 운영 성숙도, 생태계 |

임베디드는 단점을 없애는 게 아니라 *단점이 문제 안 되는 구간(단일 사용자 체험)에만 쓰고*, 그 경계를 넘으면 Neo4j 로 넘긴다. 이게 Graphiti/Cognee 가 이중 트랙을 택한 이유와 같다.

### D2. 임베디드 기본 백엔드는 Kuzu

후보를 세 능력(그래프 순회 + 벡터 ANN + 풀텍스트)과 진짜 in-process 여부로 비교했다.

| 능력 | Kuzu | FalkorDB | Neo4j (프로덕션 트랙) |
|---|---|---|---|
| 진짜 in-process (무서버) | **예** (SQLite 방식) | 아니오 (Redis 모듈 — 서버 필요) | 아니오 (서버) |
| Cypher | 자체 방언 | openCypher v9 부분집합 | 기준 방언 |
| 벡터 ANN | HNSW(`vector` 확장, 0.11.3 번들) | 있음(cosine/euclidean) | native |
| 풀텍스트 | `fts` 확장(번들) | RediSearch 기반 | native |
| 경로 순회 | `SHORTEST` / `ALL SHORTEST k`, 가변 길이 | `algo.SPpaths` 등 절차 | `allShortestPaths`, 가변 길이 |
| 시각화 | Kuzu Explorer(별도 컨테이너, 얇음) | 있음 | Browser + Bloom |
| upstream 상태 | **아카이브(2025-10), 포크 유지** | 활성 | 활성(상용) |

핵심 판정. **임베디드 트랙의 목적(무서버)을 기술적으로 충족하는 건 Kuzu 뿐이다.** FalkorDB 는 "임베디드" 라지만 Redis 모듈이라 서버 프로세스가 필요해 전제가 깨진다. Kuzu 는 진짜 in-process 이면서 Arche 가 실제로 쓰는 능력 — 벡터 인덱스 하나, 풀텍스트 하나, `id` 조회, 경로 순회 — 을 기본 번들 확장으로 다 덮는다. 잃는 건 핵심 기능이 아니라 생태계와 운영 도구 성숙도인데, Arche 의 1차 소비 경로는 에이전트가 MCP 로 JSON 을 읽는 것이라 시각화/모니터링 격차는 에이전트 경로에 영향이 거의 없다.

### D3. 기본값은 임베디드, 프로덕션 전환은 명시된 경계에서

- **기본값** — 임베디드(Kuzu). 아무 설정 없이 `pip install` 하면 임베디드로 뜬다. 온보딩의 기본 경로.
- **전환 트리거** — 다음 중 하나라도 필요해지면 Neo4j 로 넘긴다.
  1. 여러 주체가 *동시에* 적재하거나, 적재하면서 조회한다(임베디드는 단일 라이터).
  2. 여러 사용자가 같은 그래프를 namespace 로 나눠 공유한다(ADR-0015).
  3. 규모가 단일 프로세스 메모리/CPU 를 압박한다.
- **전환 방법** — 설정 플래그로 백엔드 어댑터를 고른다(ADR-0019 provider 팩토리 패턴과 대칭). 데이터 이전은 재적재(reingest)다. 임베디드 파일에서 Neo4j 로의 실시간 마이그레이션 도구는 MVP 범위 밖이다.

### D4. ADR-0004 와의 관계 — amend (supersede 아님)

ADR-0004 의 핵심 결정은 그대로 산다. "별도 벡터 DB 서비스를 두지 않고 그래프 DB 내장 인덱스를 쓴다" 는 Kuzu 에도 그대로 적용된다(Kuzu 도 벡터/풀텍스트를 자체 내장한다). 바뀌는 건 *그 내장 인덱스를 담는 컴포넌트가 Neo4j 하나로 고정됐던 것* 을 두 갈래로 연 것뿐이다. 따라서 ADR-0004 를 **amend** 한다(상단에 amendment 박스 추가). supersede 가 아니다.

### D5. "설정만 바꾸면 교체" 의 정확한 범위 — 포트 계약 수준

이중 트랙을 config-only 로 부르지만, 그건 **능력별 포트 계약 수준에서만** 사실이다. 그 아래 어댑터는 백엔드마다 별개다. Kuzu 도 Neo4j 의 Cypher 방언을 그대로 쓰지 않는다 — 벡터/풀텍스트 조회 함수, 경로 순회 문법, 인덱스 생성 구문이 다르다. 표준 GQL 이 이걸 2~3년 안에 없애주지도 않고, 아카이브된 Kuzu 는 그 수렴에 아예 못 낀다. 그러니 임베디드 트랙은 **영구적으로 두 번째 어댑터를 이고 간다** 고 봐야 한다.

이 비용을 가두는 두 가지.
- 백엔드 무관 로직(RRF 융합, BFS 절단, hub_score 계산, find_path 매핑, namespace 해소, ADR-0017 경로 점수, #142 입력 하드닝)은 도메인/서비스 계층에 있고 이미 한 번만 쓴다. Arche 는 BFS/절단/hub_score 를 Cypher 가 아니라 Python 에서 하므로, 백엔드별로 새로 쓸 질의 표면은 인덱스 조회 + 단일 홉 확장 + 경로 순회 + upsert 정도로 좁다.
- 같은 행동 계약 테스트를 두 어댑터에 똑같이 돌리는 스위트를 한 번만 짜서 드리프트를 잠근다.

### D6. Kuzu 아카이브 리스크 완화

- **버전 고정** — `kuzu==0.11.3`. 이 릴리스가 algo/fts/json/vector 확장을 기본 번들해 별도 확장 서버가 필요 없다.
- **포크 대비** — 보안/치명 버그가 나면 유지보수 포크(RyuGraph, Vela-Engineering/kuzu)로 이전하는 경로를 남긴다. 포크들은 Cypher/벡터/풀텍스트/저장 포맷을 그대로 보존한다.
- **격리** — Kuzu 특정 코드는 어댑터 한 곳에 갇히므로, 최악의 경우 임베디드 어댑터만 교체하면 되고 도메인/API/MCP 는 안 흔들린다.

## Considered Options

### 옵션 1 — FalkorDB 를 임베디드 백엔드로

거부. FalkorDB 는 "임베디드" 라 불리지만 실제로는 Redis 프로세스 안에서 도는 모듈이라, 애플리케이션이 붙으려면 Redis/FalkorDB 서버가 떠 있어야 한다. in-process 변형 FalkorDBLite 가 있으나 초기 단계다. 무서버 온보딩이라는 임베디드 트랙의 존재 이유 자체가 깨진다.

만약 이걸 택했다면, "서버 없이 pip install" 서사를 못 지켜 임베디드 트랙이 사실상 "또 다른 서버 트랙" 이 됐을 것이다. 그러면 Neo4j 를 두 개 트랙으로 나눈 것과 다를 바 없어 이중화 비용만 지고 온보딩 이득은 못 얻는다.

### 옵션 2 — 임베디드 보류, MVP 는 Neo4j-only 유지

거부. 다만 *합리적 선택이었음을 인정* 한다. 표준 GQL 이 포팅을 구해주지 않는다는 게 드러난 지금, 두 번째 어댑터는 그래프 질의를 고칠 때마다 따라오는 세금이고, MVP 목적이 가설 검증과 직접 사용이라면 그 세금을 검증 종료 전에 지는 게 과하다는 논리는 유효하다.

그럼에도 채택으로 기운 이유는 제품 정체성이다. "AI 에이전트가 MCP 로 붙는 세컨드브레인" 의 첫인상이 "먼저 Neo4j 컨테이너부터" 면 채택 곡선의 맨 앞에서 사람을 잃는다. 그리고 #145 문서 서사가 이미 무서버 온보딩을 약속으로 박아 뒀다.

만약 이걸 택했다면, #146 이 함께 보류되고 임베디드는 post-MVP 로 밀린다. 온보딩 서사와 실제 실행 경로가 어긋난 채로 MVP 를 마치게 된다.

### 옵션 3 — 파일 기반(NetworkX / igraph / Parquet), LightRAG 방식

거부. 세 인덱스(그래프 + 벡터 ANN + 풀텍스트)와 진짜 그래프 순회(가변 길이, k-최단 경로)를 한 컴포넌트로 못 준다. 벡터 ANN 과 풀텍스트를 별도 라이브러리로 붙이고 순회를 손으로 얽어야 해서, Kuzu 어댑터 하나보다 오히려 코드가 더 늘고 ADR-0017 의 경로 점수 같은 로직을 재현하기 더 까다롭다.

만약 이걸 택했다면, ADR-0004 의 "한 컴포넌트가 셋을 담당" 원칙이 깨져 인덱스 동기화 부담이 되살아났을 것이다.

### 옵션 4 — Kuzu 를 유일 백엔드로(Neo4j 폐기)

거부. 임베디드는 단일 라이터라 동시 쓰기를 못 받고, ADR-0015 의 여러 주체 namespace 공유와 규모/운영 성숙도를 감당 못 한다. 프로덕션/공유 KB 를 포기하는 셈이라 제품 범위가 좁아진다.

만약 이걸 택했다면, 이중 트랙의 이점(체험은 가볍게, 확장은 튼튼하게) 대신 임베디드의 상한이 곧 제품의 상한이 됐을 것이다.

## Consequences

### 즉시 영향

- **#146 이 착수 가능**해진다. `KuzuGraphRepository` 어댑터가 능력별 포트(GraphStore / VectorIndex / LexicalIndex)를 Kuzu 방언으로 구현한다.
- 설정 플래그가 백엔드를 고른다. 미지정 시 임베디드(Kuzu)가 기본값.
- `docker-compose.yml` 의 Neo4j 는 프로덕션 트랙용으로 남는다. 임베디드 트랙은 compose 가 필요 없다.
- ADR-0004 상단에 amendment 박스가 붙는다.

### 코드 작업 시 기억할 점 (#146)

- 두 번째 어댑터는 대략 `graph.py`(약 1,558줄) 규모다. 질의는 Kuzu 방언 — 벡터/풀텍스트 함수, `SHORTEST`/`ALL SHORTEST` 문법, Kuzu 인덱스 생성 구문.
- **행동 계약 테스트 스위트를 한 번 짜서 두 어댑터에 같이 돌린다.** namespace 격리(#98), hub_score 경로 점수(ADR-0017), 읽기 경계 clamp, 그리고 #142 입력 하드닝이 두 백엔드에서 똑같이 재현되는지 잠근다.
- Python 쪽 로직(BFS/절단/RRF/hub_score)은 백엔드 무관이라 그대로 재사용한다. 새로 쓰는 건 얇은 질의 층뿐.
- `normalized_name` 같은 2차 조회는 Kuzu 인덱싱 모델에 맞춰 구현한다(Kuzu 는 기본키 인덱싱은 강하나 임의 속성 2차 인덱스는 폭이 좁다).
- #142 의 입력 검증(`api/security.py` 의 namespace/relation_types/id 형식 검사)은 백엔드 무관이라 두 트랙에 그대로 적용된다. 다만 백엔드별 질의에서 파라미터 바인딩이 지켜지는지는 어댑터마다 다시 확인한다(Neo4j 는 clean 으로 감사됨 — ARCHITECTURE.md §8).
- `kuzu==0.11.3` 로 고정하고, 유지보수 포크 대비 경로를 README/설정 주석에 남긴다.

### 리스크

- Kuzu upstream 동결. 유지보수는 포크 의존. 완화책은 D6.
- 표준 GQL 은 2~3년 내 방언 차이를 없애주지 못하고 아카이브된 Kuzu 는 그 수렴에서 빠진다. 즉 어댑터 이중화는 상시 비용이다.
- 임베디드 트랙의 시각화/모니터링은 Neo4j 생태계보다 얇다. 운영자가 그래프를 눈으로 파고들 때만 아쉽고 에이전트 경로엔 영향 적다.
